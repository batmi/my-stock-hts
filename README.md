# MyStock HTS (Home Trading System)

[Korean](README.md) | [English](README.en.md)

[![License](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](https://opensource.org/licenses/Apache-2.0)

한국투자증권(KIS)·토스증권(TOSS) Open API 기반의 **터미널용 주식 자동매매·분석 시스템**입니다.
실시간 시세 조회, 기술적 분석, 전략 기반 자동매매, 백테스팅, AI 리포트를 하나의 CLI에서 제공합니다.

> **운용 원칙은 추세추종(Trend Following)입니다.** 손실은 빠르게 자르고 수익은 추세가 꺾일 때까지 열어 둡니다(고정 익절 없음, 샹들리에 트레일링 스탑이 주 청산). 이 원칙에 어긋나는 설정(고정 익절·반익절·RSI 과열 매도·역추세 매수)은 코드에 남아 있으나 **기본 비활성이며 설정 메뉴에도 노출되지 않습니다.**

### 면책 조항

> 본 소프트웨어는 학습·연구 목적이며 투자의 보조 수단일 뿐입니다. **모든 투자 손실의 책임은 사용자 본인에게 있습니다.**
> API 장애·네트워크 불안정·버그로 주문이 누락·중복·오체결될 수 있습니다. 비상시 즉시 프로그램을 중단하고 증권사 HTS/MTS로 직접 대응하세요.
> 실전 투자 전 반드시 **가상투자(모드 1)**로 충분히 검증하시기 바랍니다.

## 1. 기능 개요

터미널에서 시세 조회·주문·분석·자동매매를 모두 처리합니다. 메뉴 번호가 곧 기능 단위입니다.

| 메뉴 | 기능 | 내용 |
|---|---|---|
| `[0]` | 시스템 설정 | 매수/매도 전략, 스코어링·시장 국면, 리스크·자산배분, 지표 파라미터, 환경·시스템 설정. **실행 중에 바꿔도 즉시 반영되고 재시작 후에도 유지**됩니다. |
| `[1]` | 시장 지수 조회 | 국내·미국·유럽·아시아 지수, 섹터지수, 원자재(금·은·구리·원유), 환율, 미국채 금리, 암호화폐, **KRX 금현물**. 지수명 색으로 국면(강세/상승미확정/하락미확정/약세)을 표시합니다. |
| `[2]` | 종목 시세 분석 | 국내·미국 주식/ETF의 실시간 시세와 기술적 지표를 종합해 **매수 / 대기 / 상승 / 관심 / 관망 / 주의 / 매도** 상태로 판정합니다. 지수 개별 심층 분석도 제공합니다. |
| `[3]` | 종목 차트 분석 | 주봉·일봉·시봉·분봉 차트 이미지 생성, **AI 차트 이미지 판독**(Gemini Vision) 연동. |
| `[4]` | 전략 백테스팅 | 단일 종목 / **관심종목 N슬롯 포트폴리오** / **Monte Carlo**(가격에 ±1% 노이즈·슬리피지 변동·체결 누락을 섞어 1,000회 반복 → 평균·VaR 95%·표준편차) / **Walk-Forward** 검증. 매수 점수·RSI 상한·손절폭·피라미딩 차수·스코어링 가중치 조합 최적화가 함께 수행됩니다. |
| `[5]` | 시스템 트레이딩 | 자동매매 실행/중단/상태/평가/로그, **종목별 트레이딩 룰**, **트레이딩 제한 종목** 관리. |
| `[6]` | 종목발굴·재무분석 | 네이버 테마 순위, **트레이딩뷰 스크리너**(급등락 상위·갭상승·신고가 돌파·정배열 눌림목·수급 유입·낙폭과대·저평가 턴어라운드·고배당·추세 전환 9종 프리셋, 국내/미국), AI 테마 분석, AI 종목 진단, 투자 캘린더, 공시 모니터링, 수급·물량 신호, 재무 스냅샷. |
| `[7]` | 관심 종목 관리 | 국내 주식/ETF·미국 주식/ETF 등록·삭제·조회·정보 변경·메모 관리, **관심 종목 탐색**(규칙 기반 후보 발굴 후 다중 선택 추가). |
| `[8]` | 종목 주문 관리 | 매수·매도·정정·취소, **예약 주문 9종** 등록·조회. |
| `[9]` | 자산 관리 | 자산 조회, 보유 잔고, 거래 내역(엑셀 저장), 거래 평가, **포지션 분석**(직접 입력으로 미등록 자산도 판정 — 티커 `KRXGOLD`를 넣으면 금현물 보유분을 g 단위로 등록해 ATR 손절·트레일링 기준을 볼 수 있습니다), **가상투자 계좌 관리**. |

기동 시 선택하며 `--mode` 인자로도 지정합니다. 모드별로 설정 프로필이 분리되어 **검증용 설정이 실전으로 새지 않습니다.**

| 모드 | 이름 | 시세 | 주문 | 용도 |
|---|---|---|---|---|
| `1` | 가상투자(관찰) | KIS 실전 | 가상 체결 | 실시세로 장기 관찰 — 실주문 원천 차단, DB 파일 분리 |
| `2` | 한국투자증권 실전 | KIS 실전 | **실주문** | 실계좌 운용 |
| `3` | 토스증권 실전 | 토스 | **실주문** | 실계좌 운용 |

> KIS 모의투자 모드는 폐기했습니다(2026-08-26). 서버가 2 TPS로 묶여 있고 계좌를 3개월마다
> 다시 발급받아야 하는 데다, NXT·SOR 미지원과 미체결 조회 버그로 실전과 조건이 달랐습니다.
> **모드 1(가상투자)이 그 자리를 대신합니다** — 시세·지표·판정은 실전과 같은 경로를 쓰고
> 주문만 가상으로 체결합니다. 옛 `--mode 4`는 경고와 함께 모드 1로 처리됩니다.

### 주요 기능

**매매 · 시세**
- 국내/미국 주식·ETF 통합 관리, 실시간 시세와 매수/매도/정정/취소 주문
- **NXT(대체거래소)·SOR 지원** — 프리마켓(08:00~08:50)·애프터마켓(15:30~20:00) 시세·주문 지원. 08:50~09:00과 15:20~15:30은 KRX 단일가 구간이라 매매하지 않습니다. 단 **자동매매 기본 운용 시간은 KRX 정규장 09:00~15:30**입니다(지표·일봉이 모두 KRX 정규장 기준). 확장하려면 `[0] → 5-1`에서 거래 시간을 `0800`/`2000`으로 넓힙니다.
- **미국 주간거래(데이마켓)** — KIS 전용 거래소 코드(`BAQ`/`BAY`/`BAA`)로 야간 ATS 세션 시세를 반영하고, 체결이 없으면 정규장 코드로 폴백합니다.
- **장 종료 후 KRX 종가 기준**(`USE_KRX_CLOSE_AFTER_HOURS`, 기본 ON) — 모든 장이 끝난 뒤에는 현재가·지표를 KRX 정규장 종가로 고정합니다. 과거 일봉이 KRX 기준이므로 마지막 NXT 체결가가 지표를 흔들지 않게 합니다. **주문 가격은 이 설정과 무관하게 항상 실시간가**를 씁니다.
- **예약 주문 9종** — 스탑로스·돌파·지정가·시간·퀀트 점수·RSI·트레일링 매수/매도·이평선 크로스. 3초 주기 백그라운드 감시, DB 영속.

**분석 · 발굴**
- 퀀트 멀티팩터 스코어링(10점 만점)과 7단계 상태 판정
- 종목별 개별 매매 룰(점수·RSI·손절·트레일링 비율)
- 관심 종목 탐색 — 사람이 유망해 보이는 종목을 고르는 대신 **규칙으로 거르고 폭으로 채웁니다**(방어주·지주회사 등 실증상 열위 종목 배제). 후보 풀이 넓어야 슬롯이 놀지 않는다는 감사 결과에 근거합니다.
- 네이버 테마 순위 크롤링, 트레이딩뷰 스크리너 연동

**AI 어시스턴트 (Gemini)**
- 종목 심층 진단 / 지수 심층 진단 / 차트 이미지 판독(Vision) / 시장 테마 분석 / 장전 브리핑 / 장 마감 브리핑 / 관심종목 큐레이션 / 대화형 Q&A / 백테스트 성과 진단 / 매매 복기 리포트
- **안전장치**: ① 모든 프롬프트에 추세추종 기조를 주입해 반추세 조언(고정 익절·저점 분할매수)을 차단 ② 이미 백테스트로 기각된 개선안의 재제안 차단 ③ 확신도와 **반증 조건** 명시 ④ AI가 표기한 종목코드를 KRX 상장 목록과 대조해 없는 코드·시총 미달을 표시
- ※ **실시간 웹 검색(Search Grounding)은 쓰지 않습니다.** 최신 재료(매크로 지표·수급·공시)는 시스템이 직접 수집해 프롬프트에 넣습니다.

**전자공시(DART)**
- 공시 모니터링(중요도 분류 + AI 호재/악재 해석 + 공급계약·자기주식·무상증자·감자·CB/BW 상세 자동 추출)
- 투자 캘린더(주요 경제 이벤트 + 배당락 예상일·확정 배당기준일·실적발표 예상일)
- 수급·물량 신호(자기주식 결정, 메자닌 오버행, 내부자·5% 보고 순증감)
- 재무 스냅샷(매출·영업이익·순이익 증감, 분기 단독 실적, ROE·부채비율)
- 중대 공시·당일 캘린더 **텔레그램 자동 알림**

**운영**
- 텔레그램 알림·원격 제어(30여 개 명령어)
- **서킷브레이커(CB)·VI 실시간 알림** — 거래소 상태 플래그 기반
- 실행 중 설정 변경 즉시 반영, 트레이딩 제한 종목 관리
- **매매일지 웹서버 연동**(Outbox 패턴 + 백필 2단 방어)
- **프로세스 사망 감지**(외부 cron 감시자) — 알리기만 하고 자동 재기동은 하지 않습니다
- 라즈베리파이(1GB) 장기 무중단 운영을 고려한 메모리 상한·캐시 eviction

## 2. 매매 전략

> 자동매매는 관심 종목의 **국내 주식** 리스트만 대상으로 동작합니다(국내 ETF는 `SYSTEM_INCLUDE_ETF`로 선택).

### 매수 — 게이트를 모두 통과해야 진입

| # | 조건 | 기본값 |
|---|---|---|
| 1 | 종합 점수 ≥ `BUY_SCORE` | 7.0 |
| 2 | RSI < `BUY_RSI_MAX` (과열 방지, 슈퍼 모멘텀 시 완화) | 70 |
| 3 | 체결강도 ≥ `BUY_VOL_STRENGTH` (매수세 우위) | 100% |
| 4 | 지수가 기준 이평선 위 또는 이탈 밴드 안 (`MARKET_FILTER_MA`/`BAND`) | 80일 / 1% |
| 5 | 추세 품질 < `TREND_QUALITY_MAX` (모멘텀 크래시 차단) | 300 |

- **매수 우선순위**: ① 종합 점수 → ② 추세 품질 → ③ 52주 고점 근접도 → ④ 체결강도.
  추세 품질은 최근 90일 로그 종가 선형회귀의 **연환산 기울기 × R²**(Clenow 모멘텀)이며, 점수 동점(슬롯 경쟁일의 25~32%)을 가르는 연속값으로 씁니다.
- **추세 품질 상한이 있는 이유**: 높을수록 좋은 값이 아닙니다. 300 위 구간은 급등 직후 직전 승자가 가장 크게 무너지는 **모멘텀 크래시** 영역으로, 20일 전방수익이 음수로 꺾이고 꼬리가 잘립니다.
- **슈퍼 모멘텀**: 52주 고점 부근 주도주는 RSI 허용치를 완화해 추세를 끝까지 따라갑니다.
- **피라미딩**: 수익률이 `PYRAMIDING_PROFIT_TRIGGER`(+10%) 이상이고 매수 신호가 유지되는 보유 종목만 증액합니다(보유 수량의 50%, 최대 3차). **손실 종목 물타기는 구조적으로 불가능**하며, 증액분 손절률은 그 시점 ATR로 재계산되어 가중평균 손절선에 반영됩니다.

### 매도 — 우선순위 순으로 감시

1. **손절** — ATR 기반 동적 손절률(`USE_ATR_STOP`, 기본 ON). **본전 청산**: 최고 수익률이 기준을 넘으면 손절선을 +0.5%로 상향.
2. **시간 청산** — `TIME_STOP_DAYS`(15일) 경과 후에도 **손실 중**이고 상방 모멘텀을 잃은 종목만 정리(수익 중이면 시간으로 팔지 않음).
3. **트레일링 스탑 (주 청산 · 샹들리에 엑시트)** — 무장 시점을 종목 변동성이 정하고(손익분기 연동), 무장 후 고점 대비 동적 콜백만큼 하락하면 매도. **발동 배수와 콜백 배수가 분리**되어 있어 발동을 앞당겨도 청산선이 좁아지지 않습니다.
4. **추세 이탈** — 종합 점수 < `SELL_SCORE`(4.0) **그리고** 주가가 60일선 이탈(구조 훼손)일 때 전량 매도. 점수 하락 단독으로는 팔지 않아 정배열 중 눌림목에서 조기 청산되지 않습니다.

> **기본 비활성**(상방을 깎는 요소 — 메뉴 미노출, `json/dynamic_config.json` 직접 편집으로만 활성화): 고정 익절, 반익절, RSI 과열 매도, 방어적 반매도, 역추세(낙폭과대) 매수.

### 스코어링 (10점 만점, 0.5점 단위)

| 팩터 | 배점 | 구성 |
|---|---|---|

## 3. 리스크 관리

**포지션 사이징 — 세 상한의 min 결합**
매수 금액은 ① 기초 비중(집중 방지) ② 리스크 기반 상한(손실액 통제) ③ 변동성 상한(변동성 균질화)이 각자 낸 금액 중 **가장 작은 값**입니다. ②③을 곱하지 않는 이유는 ATR 손절 사용 시 두 상한이 모두 ATR에 반비례해 곱하면 사이즈가 `1/ATR²`로 과대 축소되기 때문입니다.

- **최대 보유 종목 수 · 비중 자동 연동** — 종목당 비중 기본값 `0`(자동)이면 `1 ÷ 슬롯 수`로 산출되어, 슬롯만 바꿔도 명목합이 항상 100%로 유지됩니다. 양수를 넣으면 현금 버퍼(4×0.2=80%)나 의도적 오버커밋도 허용됩니다.
- **리스크 기반 사이징** — 1회 매매의 계좌 대비 최대 손실폭 제한(기본 4%). 손절폭이 큰 종목은 비중이 자동으로 줄어듭니다.
- **포트폴리오 히트 캡** — 보유 전 종목이 동시에 유효 손절선까지 하락했을 때의 손실 합을 계좌 대비 10%(`SYSTEM_MAX_PORTFOLIO_RISK`) 이하로 제한합니다.
- **변동성 타겟팅** — ATR로 연환산 변동성을 목표치(25%)로 정규화하되, 확대 스케일이 기초 비중을 넘지 못하도록 클램프합니다.
- **리스크 동적 스케일링** — ① 국면 연동(하락 미확정 구간 ×0.6) ② 휩소율 연동(톱니장일수록 축소) ③ 계좌 드로다운 단계적 감속(-5% ×0.75, -10% ×0.5) ④ 갭 리스크 버퍼(손절폭 ×1.2). 진입 크기만 줄이고 청산 로직에는 관여하지 않습니다.

**진입 차단 · 방어**

| 장치 | 동작 |
|---|---|
| 시장 지수 필터 | 지수가 SMA80을 1% 넘게 이탈하면 신규 매수 보류, 같은 폭 회복 시 재개. 백테스트에도 동일 기준 반영 |
| 시장 방향 판단 불가 | 지수 조회 실패 시 **매수 보류**(fail-closed). 매도·손절은 지수를 참조하지 않아 계속 동작 |
| 상관계수 필터 | 보유 종목과 상관계수 0.7 이상이면 신규 매수 보류(포트폴리오 동조화 방지) |
| 기술적 필터 2단 | 추세 훼손 시 매수 보류 / ADX 45 이상 + 매도세 우위의 **투매 패닉 구간은 점수와 무관하게 원천 차단** |
| 일일 손실 제한 | 당일 자산이 한도(-10%) 초과 하락 시 **신규 매수·증액만 중단**. 청산 감시는 계속 동작하며 날짜가 바뀌면 자동 해제 |
| 손절 부재 시 매수 보류 | ATR 손절도 고정 손절도 없으면 진입하지 않음(탈출 전략 없으면 진입 금지) |
| 피라미딩 시장 게이트 | 약세 시장에서는 검증된 수익 포지션이라도 증액 보류 |
| 연속 오류 Kill Switch | API·시스템 오류 5회 연속 시 대기 모드 전환 |
| 자동매도 제외 포지션 경보 | 제한 종목·자동매매 제외 ETF가 손절선을 이탈하면 청산 대신 **텔레그램 경보**(24시간 스로틀) |

**적응형 임계값 (시장 국면)**
빠른 EMA(9일)가 느린 EMA(41일)를 교차하고 **5% 이상 진행해야 확정 추세**로 인정하는 이중 EMA 규칙입니다. 확정 전 되돌리면 휩소로 집계합니다.

| 국면 | 판정 | 매수 기준 |
|---|---|---|
| 강세 (Bull) | 상승 교차 + 5% 달성 | 완화 |
| 상승 미확정 (PendUp) | 상승 교차, 5% 미달 | 유지 |
| 하락 미확정 (PendDown) | 하락 교차, -5% 미달 = **추세 붕괴 초기** | 강화 |
| 약세 (Bear) | 하락 교차 + -5% 달성 | 강화 |

**슬리피지** — 기본 0.2%. 백테스트는 불리한 방향으로 보수 반영하고, 실매매는 체결 확률을 높이는 방향으로 주문가를 보정합니다. (대형주·ETF 0.1~0.2% / 코스닥 0.3~0.5% / 급등주 0.5~1.0%)

## 5. 설치와 실행

**요구 사항**: Python 3.10 이상, 증권사 계좌와 API 키.

```bash
# 1) 소스 받기
git clone https://github.com/your-username/my-stock-hts.git
cd my-stock-hts

# 2) 가상 환경 (권장)
python3 -m venv .venv
source .venv/bin/activate          # Windows: .venv\Scripts\activate

# 3) 의존성 설치
pip install -r requirements.txt
pip install -r requirements-dev.txt   # 개발·테스트까지 할 경우

# 4) 실행
chmod +x run.sh                    # 최초 1회
./run.sh                           # 대화형 메뉴
./run.sh --help                    # 옵션 확인
./run.sh --mode 1 --auto           # 가상투자로 자동매매 즉시 시작
```

- `run.sh`를 쓰면 가상 환경 활성화와 의존성 설치가 자동입니다. **`requirements.txt`가 의존성의 단일 소스**이며 `run.sh`가 그 파일을 읽습니다.
- `holidays` 패키지는 기동할 때마다 자동 업그레이드하지 **않습니다** — 휴장일 판정이 사람 모르게 바뀌면 매매 시간 판단이 달라지기 때문입니다. 임시공휴일 반영은 `tools/update_holidays.sh`를 주 1회 cron으로 돌리세요.
- **같은 모드는 한 서버에서 하나만 뜹니다.** 두 번째 실행은 선점 프로세스를 알리고 종료합니다 — 두 인스턴스가 텔레그램 폴링(409)·KIS 유량·DB 파일을 서로 빼앗기 때문입니다. 조회 전용으로 하나 더 띄우려면 `--allow-duplicate`를 붙이세요(실주문은 계좌 잠금이 계속 막습니다).
- Windows는 `run.bat`, 리눅스 상시 운영은 `tools/stock-hts`(tmux 세션 구성)를 참고하세요.

### 6.1 한국투자증권 (KIS)

**발급 절차**
1. 스마트폰 앱 등으로 **비대면 계좌 개설**
2. 한국투자증권 **KIS Developers** 서비스 신청
3. **마이페이지 > 내 서비스 > 발급받기**에서 App Key / App Secret 발급
4. 가상투자(모드 1)용으로 **앱키를 하나 더** 발급합니다 — TPS·웹소켓·토큰 발급 제한이 모두
   앱키 단위라, 실전과 키를 공유하면 두 인스턴스가 서로의 유량을 갉아먹습니다
5. (선택) 실시간 체결통보 WebSocket을 쓰려면 **KIS HTS 로그인 ID**를 확인해 둡니다

```sh
export REAL_APP_KEY="..."   ; export REAL_APP_SECRET="..." ; export REAL_ACC_NUM="12345678-01"
export VIRT_APP_KEY="..."   ; export VIRT_APP_SECRET="..." ; export VIRT_ACC_NUM="12345678-01"
export REAL_HTS_ID="myhtsid"                 # 선택 — 실시간 체결통보 구독키
```

- **`AUTO_*` (선택)** — 자동매매를 별도 계좌·별도 앱키로 분리할 때 씁니다. KIS의 TPS(20)·웹소켓 동시 연결(1개)·토큰 발급 제약이 **모두 앱키 단위**라, 수동 조회와 자동매매를 나누면 서로의 유량을 갉아먹지 않습니다.
- **`VIRT_*` (모드 1)** — 가상투자 전용 앱키입니다. 실전 인스턴스와 키를 나눠야 관찰 모드가 실계좌의 주문 경로를 방해하지 않습니다. `VIRT_ACC_NUM`은 **표시 전용**이며(알림 꼬리말 식별용), 내부 계좌번호는 안전장치로 항상 `PAPER`입니다.
- **`*_HTS_ID` (선택)** — 체결통보(H0STCNI0) 구독키가 HTS 로그인 ID입니다. 미설정 시 체결 감지가 REST 폴링으로 폴백합니다.
- 계좌번호는 `12345678-01` 형식(앞 8자리-상품코드 2자리)으로 넣습니다.

### 6.2 토스증권 (TOSS)

**발급 절차**
1. 스마트폰 **토스 앱**에서 토스증권 계좌 개설
2. **토스증권 개발자센터**에서 Open API 이용 신청
3. **App Key / App Secret** 발급
4. **허용 IP 등록 (필수)** — 아래 주의 참고

```sh
export TOSS_APP_KEY="..." ; export TOSS_APP_SECRET="..."
export TOSS_ACC_NUM="..."     # 선택 — 미입력 시 첫 번째 계좌 자동 선택
```

> ⚠️ **토스는 허용 IP 등록이 필수입니다.** 등록되지 않은 네트워크(모바일 테더링, VPN, 유동 IP)에서 실행하면 `IP address not allowed`로 **토큰 발급 자체가 거부**됩니다. 프로그램을 돌릴 서버/PC의 **공인 IP**를 개발자센터(앱 설정 → 허용 IP)에 등록하고, 상시 운영이라면 고정 IP 회선을 권합니다.
> KIS는 IP 등록이 필수가 아니지만 키에 '고객 IP' 제한을 걸어 뒀다면 그 IP에서만 접속됩니다. 토큰 발급 실패 시 프로그램이 사전 점검에서 **현재 공인 IP와 원인별 안내**를 출력합니다.

### 6.4 Google Gemini (AI 기능)

**발급 절차**
1. [Google AI Studio](https://aistudio.google.com/) 접속 후 구글 계정으로 로그인
2. 좌측 **Get API key** → **Create API key**
3. 발급된 키는 기본적으로 **무료 티어**로 동작합니다(일일 요청 한도 내 과금 없음)

```sh
export GEMINI_API_KEY="AIza..."
export GEMINI_MODEL="gemini-flash-latest"              # 선택 (기본값)
export GEMINI_FALLBACK_MODEL="gemini-flash-lite-latest" # 선택 — 429(한도 초과) 시 자동 전환
```

> 무료 티어는 모델당 일일 한도가 낮아 자주 걸립니다. **폴백 모델을 비워 두지 마세요** — 한도 초과(429)나 서버 과부하(503) 시 자동으로 폴백 모델에 재시도합니다.

### 6.5 OpenDART (전자공시)

국내 **공시 모니터링 · 배당/실적 캘린더 · 수급/물량 신호 · 재무 스냅샷**에 쓰입니다. 미설정 시 해당 기능만 비활성화되며 해외 종목 배당·실적은 yfinance로 키 없이 조회됩니다.

**발급 절차**
1. [OpenDART](https://opendart.fss.or.kr) 접속 → 우측 상단 **인증키 신청/관리 > 오픈API 이용신청**
2. 이메일 등 기본 정보 입력 후 신청 (가입 즉시 발급, 무료)
3. 메일로 받은 **40자리 인증키** 확인 (또는 *인증키 신청/관리 > 오픈API 인증키*)

```sh
export DART_API_KEY="40자리_인증키"
```

> 일일 호출 한도 20,000건이며 관심종목만 하루 단위로 조회하므로 한도 내에서 충분합니다.
> 최초 실행 시 종목코드↔DART 고유번호 매핑을 내려받아 `json/dart_corp_map.json`에 캐시합니다(월 1회 자동 갱신).

### 6.6 FRED (미국 경제지표 일정)

`[6] → 5. 투자 캘린더` 상단의 **미국 지표 발표일**(CPI·고용보고서·PCE·PPI·GDP·소매판매·JOLTS)에만 필요합니다. FOMC 일정은 연준 공식 캘린더에서, 국내·미국 선물옵션 동시만기는 자체 계산으로 받아 **키 없이도 동작**합니다.

**발급 절차**
1. [FRED API Keys](https://fredaccount.stlouisfed.org/apikeys) 접속 → 계정이 없으면 **Create New Account**로 무료 가입(이메일 인증)
2. 로그인 후 **Request API Key** → 사용 목적을 간단히 입력하고 신청 (즉시 발급)
3. 발급된 **32자리 키** 확인

```sh
export FRED_API_KEY="32자리_키"
```

> 발표 '예정일'을 미래분까지 제공하므로 표시되는 날짜는 추정이 아니라 **확정된 공식 발표일**입니다(미국 현지시각 기준). 결과는 `json/econ_calendar_cache.json`에 하루 단위로 캐시됩니다. 한국은행 금통위처럼 기계 판독이 불가능한 일정은 `json/econ_calendar_seed.json`에 수기로 등록할 수 있습니다.

### 6.7 TradingView (지수·미국채 조회 안정화)

별도 발급이 아니라 **기존 TradingView 계정의 로그인 ID/비밀번호**입니다. 지수·미국채 금리 조회에 쓰는 tvDatafeed가 로그인 모드로 동작해 익명 대비 조회 한도와 안정성이 좋아집니다.

```sh
export TV_USERNAME="tv_id"
export TV_PASSWORD="tv_password"
```

- 미설정 시 익명(nologin)으로 동작하며 파일 로그에 WARNING이 남습니다(로그인 성공 시 INFO).
- 발급 토큰은 `data/tv_token.json`에 **7일간 캐시**되어 재시작마다 재로그인하지 않습니다 — 잦은 로그인은 TradingView **캡차**를 유발합니다. 캡차가 뜨면 잠시 후 재시도하거나 브라우저에서 한 번 로그인한 뒤 재시작하세요.

### 6.8 KRX 정보데이터시스템 (`KRX_ID` / `KRX_PW`)

API 키가 아니라 **[data.krx.co.kr](https://data.krx.co.kr) 회원 계정의 웹 로그인 ID/비밀번호**입니다. 홈페이지에서 무료 회원가입 후 그대로 넣습니다.

```sh
export KRX_ID="krx_id"
export KRX_PW="krx_password"
```

> ⚠️ **비밀번호이므로 다른 곳에 쓰지 않는 전용 계정을 권합니다.** 설정 후 반드시 재시작해야 하며, 이미 떠 있는 프로세스는 이 값을 받지 못합니다.

이 자격증명이 켜고 끄는 것 — 없으면 모두 대체 소스로 **조용히 폴백**하므로 동작 자체는 같지만 데이터 품질이 달라집니다.

| 항목 | KRX 공식 | 폴백과의 차이 |
|---|---|---|
| 과거 일별 수급 | 기간 지정 조회 | KIS 수급 TR은 **최근 30거래일만** 제공 → 다년 백테스트에서 그 창 밖 '스마트머니'가 통째로 꺼짐 |
| KRX 금현물 | 실제 OHLC + 거래량 | 네이버는 **종가만** → 봉 평탄화로 ATR·ADX 왜곡, 거래량이 없어 OBV 불가 |
| 코스피200·코스닥150 일봉 | 확정 봉 + 거래량 | tvDatafeed는 간헐 빈 응답에 지수 거래량 0. **코스닥150은 야후·FDR에 티커가 없어** 단일 실패점이었음 |
| 상장 종목 목록 | 종목명·시가총액 | AI 출력의 종목 검증에 사용(KONEX는 FDR로 보충) |

> KRX는 **마감 후 확정 봉만** 주므로 장중 현재가는 종전 실시간 소스가 담당합니다.
> **V코스피200·코스피200선물은 모드 2(한투 실전) 전용입니다.** 둘 다 대체 실시간 소스가 없고, KRX 확정 봉으로 메우면 장중 내내 묵은 값이 됩니다 — 선물은 세션이 하루를 거의 덮어(주간 09:00~15:45 · 야간 18:00~06:00) 최대 하루까지 벌어지고(야간장 실측 40포인트 괴리), 변동성지수는 하필 변동성이 튀는 순간에 화면만 조용해집니다. 부정확한 값을 보여 주는 대신 토스 모드의 지수 목록에서 뺐습니다.

### 6.9 매매일지 웹서버 연동

체결 내역을 원격 매매일지 웹서버([stock-memo](https://github.com/batmi/stock-memo))로 전송합니다. 프로토콜은 두 프로젝트가 공유하는 [`UniversalTradingHistoryAPI.json`](UniversalTradingHistoryAPI.json)(OpenAPI 3.1) 계약을 따릅니다.

1. **사용 스위치**: `[0] → 5. 환경 및 시스템 설정 → 3. 데이터·통신 → 매매일지 웹서버 연동` (기본 OFF)
2. **API 키 발급**: 웹 대시보드 → **설정 → HTS 연동 API 키**

```sh
export JOURNAL_API_URL="https://memo.example.com"   # 필수 (HTTPS 권장 — 키가 평문으로 나가지 않도록)
export JOURNAL_API_KEY="skm_..."                    # 필수
export JOURNAL_SOURCE="my-stock-hts"                # 선택 — 설치(기기)마다 달라야 함
export JOURNAL_BOT_ID=""                            # 선택 (기본 JOURNAL_SOURCE)
export JOURNAL_BOT_LABEL=""                         # 선택 — 웹 표시명(기본 자동 생성)
```

> 스위치와 URL·KEY가 **모두** 갖춰져야 동작하며, 빠진 항목은 메뉴가 안내합니다.
> 여러 대를 돌린다면 `JOURNAL_SOURCE`는 기기마다 달라야 합니다(같으면 백필 기준점이 서로를 덮어 누락이 생깁니다).

## 8. 아키텍처와 안정성

**동시성**
- **DB 작업 큐 프록시** — 모든 DB 쓰기를 단일 워커 큐로 라우팅해 다중 스레드의 `database is locked`를 원천 차단합니다.
- **전역 스레드 풀** — 무분별한 스레드 생성 대신 AI·IO·텔레그램 풀을 재사용합니다.
- **Thread-safe 동적 설정** — 실행 중 설정 변경에 `RLock`을 적용하고 **Pydantic**으로 타입·범위를 검증합니다.

**주문 안전**
- **주문 상태 머신** — 접수→체결→취소→부분체결 전 단계를 추적해 중복 주문·유령 포지션을 방지합니다. 주문 응답이 유실되면 재전송하지 않고 **당일 주문내역 조회로 대사**합니다.
- **Kill Switch** — 오류가 연속 발생하면 계좌 보호를 위해 대기 모드로 전환합니다.
- **단일 실행 보장** — 같은 앱키로 다른 프로세스가 떠 있으면 기동 시 경고합니다(TPS·웹소켓·토큰 제약이 앱키 단위이므로).

**시세 정합성**
- **실시간 시세 단일 적용** — 분석 화면과 자동매매가 같은 당일 시세로 지표를 계산하도록 보정 로직을 단일 진입점(`indicators.apply_realtime_price`)으로 통합했습니다.
- **WebSocket 실시간 시세·체결통보** — KIS WS로 현재가·체결강도를 push 수신하고(미구독·끊김 시 REST 자동 폴백), 체결통보(AES256-CBC 복호화)로 체결 확정을 즉시 깨웁니다. 단일 연결당 41건 제한이 있어 **보유종목 → 매수후보 순으로 시스템 트레이딩 종목을 항상 구독**하고 남는 슬롯을 로테이션합니다. `USE_WEBSOCKET`은 재시작 없이 즉시 적용됩니다.
- **백테스트–실매매 데이터 일치** — 국내 백테스트는 모드와 무관하게 KRX 공식(pykrx/FDR)을 씁니다. 확보 기간이 요청보다 짧으면 **경고**로 알려 조용한 절단을 막습니다.

**관측·운영**
- **신호 원장(Signal Ledger)** — 체결강도·매도잔량비·재진입 차단처럼 일봉으로 재현 불가능한 실매매 게이트의 판정을 DB에 **(일자, 종목)당 1행** 누적합니다(기본 3년 보존). "그날 한 번도 통과 못함"과 "일부 주기만 막힘"이 구분되며, 자동매매 로그도 일반 로그(30일)와 분리해 120일 보존합니다. 분석: `python3 tools/audit_signal_ledger.py`
- **프로세스 사망 감지** — 살아 있는 프로세스가 1분마다 `logs/heartbeat.json`에 다음 도장 시각(deadline)을 약속하고, 외부 cron 감시자(`tools/hts_watchdog.py`)가 그 약속만 확인합니다. **자동 재기동은 하지 않습니다** — 원인을 모른 채 되살리면 같은 이유로 다시 죽거나 반쯤 살아 주문을 냅니다. 정상 종료에는 알림이 가지 않습니다.
- **모드별 설정 프로필** — 실전은 기준 파일만 읽고 쓰며, 다른 모드는 기준 위에 자기 프로필을 얹습니다(차이값만 기록). 관찰 모드에서 끈 안전장치가 실전으로 새지 않고, 승격은 수동입니다.
- **메모리 보호** — 시세·차트 캐시에 항목 수 상한을 두고 초과 시 오래된 항목부터 제거해 라즈베리파이(1GB)에서도 무제한 증가하지 않습니다.

**API 효율 (TPS 최적화)**
- **적응형 동적 TPS(AIMD)** — 성공이 쌓이면 실효 TPS를 올리고 `EGW00201` 발생 시 즉시 백오프해 적정값으로 자가 수렴합니다.
- **NXT 시간대 게이팅** — 정규장에는 NXT 보조 조회를 생략해 종목당 호출을 약 절반으로 줄입니다.
- **일봉 디스크 영속 캐시** — 거래일 단위로 보존해 재시작 후에도 같은 날은 재조회하지 않습니다.
- **불필요 호가 조회 생략**, **워커 수를 TPS에 정합**.

## 10. 예약 주문

증권사 HTS의 단순 가격·시간 예약을 넘어 **퀀트 점수·기술적 지표 기반**으로 예약합니다. 백그라운드 스레드가 3초 주기로 감시하며 SQLite에 저장되어 재시작 후에도 유지됩니다.

| 유형 | 발동 조건 |
|---|---|
| STOP | 목표가 이하로 하락 (익절/손절 매도) |
| BREAKOUT | 저항선 상향 돌파 (추격 매수) |
| LIMIT | 지정가 터치 |
| TIME | 지정 시각 도달 (예: 15:20) |
| SCORE | 퀀트 점수가 설정치 도달·이탈 |
| RSI | RSI가 기준선 돌파·이탈 |
| TRAILING_BUY | 최저점 대비 N% 반등 (바닥 낚시) |
| TRAILING_SELL | 최고점 대비 N% 하락 (이익 보전) |
| EMA | 이동평균선 상향 돌파·하향 이탈 |

**보호 로직**
- **유효 기간**(당일/이번 주/이번 달/무기한) 만료 시 자동 취소
- **중복 매매 방지** — 예약 매도가 걸린 종목을 전량 매도하면 대기 중 예약이 자동 소멸(신규 매수 시 과거 예약 매수도 자동 취소)
- **네트워크 절약** — 장 마감(20:00~08:00)과 단일가 동기화 시간(08:50~09:00, 15:20~15:30)에는 시세 조회를 차단
- **시장가 대체** — 실행 단가를 `0`으로 두면 발동 시점의 현재가로 보정해 전송

### 매매일지 연동 동작 방식

체결 경로에서는 네트워크를 타지 않습니다. `insert_trade()`가 거래 기록과 **같은 트랜잭션**으로 `journal_outbox`에 적재하고, 백그라운드 워커가 30초 주기로 배치 전송합니다(실패 시 지수 백오프). 서버가 멱등키로 중복을 걸러내므로 재전송은 언제나 안전합니다.

| 장애 상황 | 막아 주는 것 | 복구 |
|---|---|---|
| 웹서버 다운·네트워크 단절 | 1단 큐 | 복구 시 자동 전송 |
| 연동 토글 OFF·환경변수 누락 | 2단 백필 | 로컬 `trades`를 서버의 마지막 동기화 지점과 대조해 회수 (기동 60초 후 1회, 이후 6시간 주기) |

- **전송 대상**: `체결`(CONFIRMED)·`체결(추정)`(ESTIMATED)만 보내고 `접수`/`취소`는 보내지 않습니다.
- **가상투자(모드 1)**: 같은 스위치로 켜고 끕니다. 전송되는 체결은 `isSimulated=true`로 실려 서버에서 실거래 기록·통계와 분리 보관되며, 봇 식별자도 `…:paper:PAPER`로 갈려 실전봇의 상태 칸을 덮어쓰지 않습니다. 스위치는 모드별 프로필(`dynamic_config.paper.json`)에 저장되므로 가상에서 켠 것이 실전으로 새지 않습니다.
- **`isSystem` 분류**: `(AUTO)` 태그가 붙은 AutoTrader 주문만 `true`입니다. 예약 주문은 실행이 무인이어도 **조건을 건 주체가 사람**이라 시스템으로 보지 않습니다.
- **웹에서 지운 기록**은 자동으로 다시 보내지 않습니다(의도적으로 지운 기록이 되살아나면 지울 방법이 없어집니다). 되살리려면 웹 **계정 설정 → 재동기화**를 쓰세요. **백업에서 복원했다면 반드시 재동기화가 필요합니다.**
- 검증: `python tools/journal_sync_e2e.py [--cleanup]` — 가상 체결로 `적재 → 전송 → 되읽기 → 필드 대조`까지 운영과 같은 경로를 태웁니다.
