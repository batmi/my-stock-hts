# MyStock HTS (Home Trading System)

[Korean](README.md) | [English](README.en.md)

[![License](https://img.shields.io/badge/License-Apache_2.0-blue.svg)](https://opensource.org/licenses/Apache-2.0)

한국투자증권(KIS) 및 토스증권(TOSS) Open API를 활용한 파이썬 기반의 개인용 주식 자동매매 및 분석 시스템입니다.
터미널(Console) 환경에서 동작하며, 실시간 시세 조회, 정밀한 기술적 분석, 그리고 전략 기반의 자동매매 기능을 제공합니다.

> **본 시스템 트레이딩의 기본 원칙은 추세추종(Trend Following)입니다.** 손실은 빠르게 자르고 수익은 추세가 꺾일 때까지 열어두며(고정 익절 미사용, 샹들리에 트레일링 스탑 주청산), 강하고 오래 지속되는 추세의 종목만 선별 매수합니다. 이 원칙에 위배되는 설정(고정 익절·반익절·RSI 과열 매도·방어적 반매도·역추세 매수)은 코드에 보존되어 있으나 기본 비활성이며, 설정 메뉴에서도 노출되지 않습니다.

## 1. 프로그램 개요 및 목적 (Overview & Objective)

이 프로그램은 **기술적 분석을 중시하는 퀀트(Quant) 및 시스템 트레이더**를 위해 설계된 CLI(Command Line Interface) 기반의 올인원 주식 도구입니다.
무거운 HTS(홈 트레이딩 시스템) 없이도 터미널 환경에서 빠르고 직관적으로 시세 조회, 잔고 확인, 주문 실행을 수행할 수 있으며, 감에 의존하기보다 **데이터와 지표(EMA 정배열, RSI, MACD 등)**에 근거하여 매매 타이밍을 잡을 수 있도록 돕습니다.

### 주요 특징
*   **HTS/MTS 대체:** 터미널에서 실시간 시세 조회 및 매수/매도/정정/취소 주문 실행
*   **NXT(대체거래소) 및 SOR(최적주문집행) 완벽 지원:** 정규장(KRX)뿐만 아니라 넥스트레이드(NXT) 운영 시간(08:00~08:50, 15:30~20:00)에도 실시간 시세 연동 및 자동/수동/예약 매매 완벽 지원 (단, 모의투자는 KIS API 스펙상 지원 불가)
    *   단, **시스템 트레이딩의 기본 운용 시간은 KRX 정규장 09:00~15:30**입니다. 지표·일봉이 전부 KRX 정규장 기준(pykrx/FDR)이라 매매 시간대도 같은 기준으로 맞춘 것입니다. NXT 연장거래까지 자동매매로 운용하려면 설정 `[0] → 5-1. 거래 시간·주기`에서 시작/종료를 `0800`/`2000`으로 넓히면 됩니다.
*   **엔터프라이즈급 예약 주문:** HTS의 한계를 뛰어넘는 퀀트 점수, RSI, 트레일링 기반의 24시간 백그라운드 예약 매매 지원
*   **기술적 분석 자동화:** 복잡한 보조지표 계산을 자동화하여 **'매수/대기/상승/관심/관망/주의/매도'** 등의 직관적인 투자 판단 신호 제공
*   **개별 종목 전략 설정:** 종목별로 다른 매수/매도 기준(점수, RSI)과 익절/손절/트레일링 스탑 비율을 개별적으로 설정 가능
*   **개별 지수 심층 분석:** 코스피, 나스닥 등 시장 지수에 대한 상세 차트 제공 및 매크로 환경을 결합한 AI 심층 리포트 지원
*   **AI 투자 어시스턴트:** Google Gemini LLM을 활용한 종목 심층 진단, 시장 주도 테마 분석, 대화형 Q&A 및 장전 시황 브리핑 제공
*   **전자공시(DART) 연동:** OpenDART API를 활용한 관심종목 **공시 모니터링**(중요도 분류 + AI 호재/악재 해석 + 공급계약·자기주식·무상증자 등 상세 자동 추출), **배당·실적 캘린더**(확정 배당기준일 파싱·실적발표 예상일), **수급·물량 신호**(자기주식 결정·메자닌 오버행·내부자/5% 보고), **재무 스냅샷**(분기 단독 실적·ROE·부채비율), **중대 공시 텔레그램 실시간 알림** 제공
*   **시장 지수 필터링:** KOSPI/KOSDAQ 지수의 추세를 분석하여 하락장에서는 자동으로 매수를 보류하는 리스크 관리 기능
*   **시장 정지(서킷브레이커/VI) 실시간 알림:** 거래소의 실제 상태 플래그 기반으로 시장 서킷브레이커(CB)와 종목별 변동성완화장치(VI) 발동/해제를 감지해 텔레그램으로 즉시 알림 (CB 기본 ON, VI는 옵션)
*   **포트폴리오 동조화 방지 (상관계수 필터링):** 보유 중인 종목과 주가 흐름이 유사한(상관계수 0.7 이상) 종목의 중복 매수를 차단하여 포트폴리오 다각화 유도
*   **실시간 설정 변경:** 시스템 트레이딩 실행 중 매수/매도 조건 및 투자 비중을 즉시 변경하고 영구 반영하는 기능
*   **트레이딩 제한 종목 관리:** 특정 종목을 시스템 트레이딩 대상에서 제외(매수/매도 제한)하고, 매수 시그널 발생 시 알림만 받도록 설정 가능
*   **국내/해외 통합 관리:** 한국투자증권(KIS) API를 활용하여 국내 주식과 미국 주식을 하나의 인터페이스에서 통합 관리
*   **실전/모의 투자 지원:** 설정 변경만으로 모의 투자와 실전 투자를 손쉽게 전환
*   **전략 백테스팅:** 과거 데이터를 기반으로 현재의 매매 전략을 검증하고 수익률을 시뮬레이션
*   **엔터프라이즈급 안정성 및 성능 최적화:** 
    *   **Pydantic** 기반의 엄격한 동적 설정값(Configuration) 검증 및 Thread-safe 아키텍처
    *   API 병목 및 OS 자원 낭비를 막는 **전역 스레드 풀(Thread Pool) 재사용 메커니즘** 및 독립된 백그라운드 스케줄러 구동
    *   작업 큐(Queue) 기반의 DB 프록시 아키텍처를 도입하여 다중 스레드 환경의 **SQLite Lock 문제 원천 차단**

## 2. 매매 전략 개요 (Trading Strategy)

> **안내:** 시스템 트레이딩(자동매매)은 '관심 종목 관리' 메뉴에 등록된 **'국내주식' 리스트를 대상으로만 작동**합니다.

본 시스템은 **추세 추종(Trend Following)** 전략을 기반으로 하며, 다각적인 기술적 분석을 통해 확률 높은 진입 시점을 포착하고 철저한 리스크 관리를 수행합니다.

> **추세추종 기조 (핵심 원칙)**: ① 손실은 제한하고 수익은 열어둔다 — 고정 익절 천장 없이 **트레일링 스탑(샹들리에 엑시트)**이 주 청산 수단입니다. ② 강하고 오래 지속되는 추세를 매수한다 — 매수 우선순위는 **추세 품질(회귀 모멘텀)** → 점수 → 52주 고점 근접도 → 체결강도 순이며, 추세의 강도는 스코어링의 **가격 모멘텀(절대 모멘텀)** 팩터로 평가합니다. 수익으로 추세가 검증된 포지션만 **피라미딩(증액)**하며, 손실 종목 추가매수(물타기)는 구조적으로 불가능합니다. ③ 추세는 시장이다 — 지수가 기준 이평선 아래면 신규 매수를 보류합니다.

> 이 섹션은 전략의 **개념**을 설명합니다. 각 조건의 발동 기준값(기본값)과 파라미터 상세는 **[3. 전략 파라미터 상세](#3-전략-파라미터-상세-configuration)** 를 참고하세요. (모든 수치는 설정으로 변경 가능)

### 1. 매수 전략 (Buy Strategy)
매수는 **퀀트 멀티팩터 모델(Quant Multi-Factor Model)**을 통해 산출된 종합 점수와 필터링 조건을 모두 만족할 때 실행됩니다.

*   **진입 조건 (AND 조건)**:
    1.  **종합 점수**: 매수 기준 점수(`BUY_SCORE`) 이상 — 스코어링 기준은 아래 [3. 스코어링 기준](#3-스코어링-기준-scoring-system) 참고
    2.  **과열 방지**: RSI가 허용 상한(`BUY_RSI_MAX`) 미만 (슈퍼 모멘텀 발동 시 완화)
    3.  **수급 확인**: 체결강도가 기준(`BUY_VOL_STRENGTH`) 이상 (매수세 우위)
    4.  **시장 필터**: KOSPI/KOSDAQ 지수가 기준 이평선(`MARKET_FILTER_MA`) 위에 위치 (하락장 회피)

*   **매수 우선순위 (게이트와 랭킹의 분리)**: 진입 조건(게이트)을 통과한 후보가 여럿이면 **① 추세 품질 → ② 종합 점수 → ③ 52주 고점 근접도 → ④ 체결강도** 순으로 매수합니다.
    *   **추세 품질 (회귀 모멘텀)**: 최근 90일(`TREND_QUALITY_LOOKBACK`) 로그 종가 선형회귀의 **연환산 기울기 × R²** (Clenow 모멘텀). 기울기는 추세의 강도, R²는 매끄러움(지속성)을 재므로, 급등락 끝에 우연히 정배열에 걸린 종목은 뒤로 밀리고 꾸준히 우상향한 주도주가 우선됩니다. 점수는 이진 신호 합산이라 동점이 흔해 '진입 자격' 게이트로만 쓰고, 후보 간 우열은 연속값인 추세 품질로 가립니다.

*   **주도주 추종: 슈퍼 모멘텀 (Super Momentum)**:
    *   신고가(52주 고점) 부근에서 강력한 랠리를 펼치는 주도주의 경우, 일반적인 과열 기준(매수/매도 허용 RSI)을 완화하여 시장의 강력한 추세를 끝까지 따라가는 전략입니다.

*   **피라미딩: 수익 포지션 증액 (Pyramiding)**:
    *   수익률이 트리거(`PYRAMIDING_PROFIT_TRIGGER`, 기본 +10%) 이상이고 매수 신호(추세)가 유지 중인 보유 종목에 한해, 보유 수량의 일정 비율(`PYRAMIDING_RATIO`, 기본 50%)을 **1회 한정(기본)** 증액합니다.
    *   물타기의 정반대 개념으로, **손실 중인 종목에는 절대 발동하지 않습니다.** 증액분의 손절률은 증액 시점의 ATR로 재계산되어 가중평균 손절선에 반영됩니다.

*   **하락장 전용: 낙폭과대 역추세 매수 (Mean Reversion)** — **기본 비활성 (메뉴 미노출)**:
    *   과매도 구간의 기술적 반등을 노리는 전략이나, 추세추종과 상반된 엣지(짧은 되돌림 목표·타이트 손절이 필요)라 현재 청산 체계와 부정합하고 슬롯 기회비용이 커서 **기본설정과 모든 프리셋에서 비활성화**되어 있으며, **설정 메뉴에도 노출되지 않습니다**. (재활성화는 `json/dynamic_config.json` 직접 편집으로만 가능)

### 2. 매도 전략 (Sell Strategy)
**"손실은 빠르게 자르고, 수익은 추세가 꺾일 때까지 열어둔다"**는 추세추종 기조에 따라, 고정 익절 천장 없이 다음 순서로 청산 조건을 감시합니다. (우선순위 적용)

1.  **손절 (Stop Loss)**: 손실률이 한계치에 도달하면 즉시 매도. `USE_ATR_STOP` 사용 시 매수 시점 변동성(ATR) 기반의 동적 손절률을 적용합니다.
    *   **본전 청산 (Break Even Stop)**: 달성한 최고 수익률이 발동 기준 이상이면 손절선을 본전 수익권(+0.5%)으로 자동 상향하여 수익의 손실 전환을 차단
2.  **시간 청산 (Time-based Stop)**: 설정 기간 경과 후에도 **손실 중**이고 상방 모멘텀을 상실한 종목만 정리 (수익 중인 종목은 시간으로 매도하지 않음 / 상승 추세 유지 시 유예)
3.  **트레일링 스탑 (Trailing Stop) — 주 익절 수단 (샹들리에 엑시트)**: 발동 수익률 도달 후, 고점 대비 `TS 전용 ATR 배수` 기반의 동적 콜백만큼 하락하면 매도. 급등주는 변동성에 비례해 콜백이 자동으로 넓어져 추세를 끝까지 추종합니다. (`TS_MAX_GIVEBACK_RATIO=0` 기본값은 반납 상한 캡을 해제한 순수 샹들리에 — 양수로 설정하면 최대 수익의 해당 비율 이상 반납을 차단)
4.  **추세 이탈 (Trend Broken)**: 종합 점수가 매도 기준(`SELL_SCORE`, 기본 4.0) 미만으로 하락**하고 주가가 60일선을 이탈**(추세 구조 훼손)했을 때 전량 매도. 점수 하락 단독으로는 팔지 않아 정배열 유지 중의 통상적 눌림목에서 조기 청산되지 않으며, 상태가 '매도'로 분류되면 즉시 매도합니다.

> **전략 프리셋 폐지 (2026-07-20)**: 시장 국면별 전략 프리셋(강세/약세/횡보)은 백테스트 검증 결과 폐지했습니다. 30종목×3.8년 기준 강세 프리셋은 기본설정과 사실상 동일했고(17.15% vs 17.48%), 약세 프리셋은 수익을 1/3로 깎으면서 >30% 대박 거래를 29건→15건으로 절반 잘라냈으며(PF 1.70→1.29), 횡보 프리셋은 `BUY_RSI_MAX=50`과 슈퍼모멘텀 OFF가 논리적으로 충돌해 **3.8년간 매매를 한 건도 하지 못했습니다**. 국면 대응은 이미 시장 필터·국면/휩소율 리스크 스케일링·드로다운 감속·적응형 매수 임계값으로 자동화되어 있어, 사람이 국면을 수동 판정해 전략을 통째로 교체하면 자동 판정과 이중으로 충돌합니다. (설정 메뉴 7번과 텔레그램 `/preset` 제거)

> **기본 비활성 옵션 (상방 제한 요소, 메뉴 미노출)**: 고정 익절(`TAKE_PROFIT_RATE=0`), 반익절(`HALF_TAKE_PROFIT_USE=False`), RSI 과열 매도(`TAKE_PROFIT_RSI=0`), 방어적 반매도(`DEFENSIVE_HALF_SELL_USE=False`)는 수익의 fat-tail을 잘라내므로 기본설정과 모든 프리셋에서 꺼져 있으며, **추세추종 원칙 보호를 위해 설정 메뉴에서도 노출되지 않습니다**. 재활성화는 `json/dynamic_config.json` 직접 편집 또는 종목별 개별 룰(자동매매 메뉴)로만 가능합니다.

### 3. 스코어링 기준 (Scoring System)
매수 여부를 판단하는 종합 점수는 **퀀트 멀티팩터 모델**에 기반하여 계산됩니다. (총점 10점 만점, 0.5점 단위)
*각 팩터의 배점은 설정(`SCORING_WEIGHTS`)을 통해 조절 가능하며, 아래는 기본값 기준입니다.*

1.  **Trend Factor (추세 팩터) [기본 4.0점]**
    *   **이동평균**: 현재가 > 20일선(+0.5), 20/60/120선 정배열(+1.0), 5일선이 20일선 상회(+0.5) — 상호 상관이 높은 EMA 신호 군집의 합산은 **상한 2.0점**으로 제한 (과대 가점 방지)
    *   **초기 추세 전환**: 20일선 ≤ 60일선(역배열/조정) 시 주가 > 60일선 돌파(+0.5)
    *   **추세 지속 이력**: 최근 120일(`TREND_PERSIST_LOOKBACK`) 중 종가가 60일선 위였던 비율 ≥ 70%(`TREND_PERSIST_MIN`) (+0.5) — 순간 상태가 아닌 '유지된 기간'을 재는 지속성 신호로, 갓 골든크로스한 미검증 추세와 오래 지속된 추세를 점수로 구분합니다.
    *   **MACD**: MACD > Signal 골든크로스(+0.5), MACD 히스토그램 양수 또는 상승(+0.5)
    *   **SAR**: 주가 > SAR (상승 추세 +0.5)

2.  **Momentum Factor (모멘텀 팩터) [기본 2.5점]**
    *   **RSI**: RSI ≥ 50 강세 구간(+0.5), RSI ≥ 60 모멘텀 확장(+추가 0.5), 40 ≤ RSI < 50 상승 여력 구간(추세 구조[주가>60일선] 위의 눌림목일 때만 +0.5)
    *   **CCI**: CCI > 0 상승 추세(+0.5) 또는 과매도권(-100) 탈출(추세 구조 위일 때만, 둘 중 하나만 +0.5)
    *   **DMI**: +DI > -DI 교차(+0.5)
    *   **가격 모멘텀 (절대 모멘텀)**: 6개월(`MOMENTUM_LOOKBACK`) 수익률 양수 AND 52주 위치 ≥ 80%(`MOMENTUM_W52_NEAR`) — 신고가 부근 주도주 가점(+0.5). '강한 종목을 매수하라' 원칙으로, 지표만 좋은 바닥권 종목과 신고가 랠리 종목을 점수로 구분합니다.
        *   **다중 기간 정합 게이트**: 1개월·3개월(`MOMENTUM_LOOKBACK_1M/3M`) 수익률이 음수면 위 가점을 보류합니다. 6개월 누적만 좋고 최근 1~3개월이 꺾인 **'식어가는 추세'**의 고점 진입을 차단합니다.

3.  **Strength & Volume Factor (강도 및 수급 팩터) [기본 1.5점]**
    *   **ADX**: ADX ≥ 20 추세 형성 확인(+0.5)
    *   **거래량**: 20일 평균 대비 거래량 폭증(200%+) & 양봉(+0.5)
    *   **OBV 및 Smart Money**: OBV 상승 & 메이저 수급 턴어라운드(+0.5)

4.  **Synergy Bonus (상관관계 가산점) [기본 2.0점]**
    *   **추세 시작**: 주가 > 60일선 AND MACD 양수(또는 확산) AND ADX ≥ 20 (+1.0)
    *   **모멘텀 폭발**: MACD 양수(또는 확산) AND (RSI ≥ 60) AND (OBV 상승) (+1.0)

#### 점수대별 판단 기준 (Scoring Guide)
*   **8.5점 ~ 10.0점 (Strong Buy)**: **강력 매수**. 모든 지표가 상승을 가리키며 상관관계까지 완벽한 상태입니다. 비중을 실어 진입할 수 있습니다.
*   **7.0점 ~ 8.5점 (Buy)**: **매수**. 추세는 확실하나 일부 보조지표가 아직 따라오지 못한 상태입니다. (시스템 기본 매수 기준 점수 `BUY_SCORE` = 7.0) 분할 매수로 진입하기 좋습니다.
*   **매수 대기 (Wait / 대기, 점수 ≥ `BUY_SCORE`)**: **대기**. 점수는 매수 기준(`BUY_SCORE`)을 충족했으나 단기 **RSI가 과열 구간**(`BUY_RSI_MAX` 이상, 단 과열 주의선 미만)이라 즉시 진입만 보류한 상태입니다. "너무 강해서 잠깐 기다리는" **눌림목 매수 대기**이며(약세·위험을 뜻하는 '주의'와 정반대), 상승과 동급(같은 색·시간청산 유예·스크리닝 노출)으로 취급됩니다. RSI가 식으면 자동으로 '매수'로 전환됩니다. (RSI가 과열 주의선까지 더 오르면 '주의'로 강등)
*   **6.0점 ~ 7.0점 (Rise / 상승)**: **상승**. 추세가 정렬되어 살아있으나 점수가 매수 문턱에 약간 못 미친 상태입니다. (점수 축적 대기, `RISE_SCORE` = 6.0)
*   **관심 (Interest / 태동, 점수와 무관)**: 아직 추세 정렬은 **미완성**이나 추세 전환 **초기 신호가 일정 개수 이상**(`INTEREST_SIGNAL_MIN`) 포착되고 명백한 위험 신호가 없는 단계입니다. 실제 매수 단계로 발전할지 빠르게 인지하기 위한 **수동 스윙(단기) 매매 모니터링** 용도이며, 자동매매 매수 대상은 아닙니다. (초기 신호 7종 등 상세 조건은 3-2 참고)
*   **4.0점 미만 (Sell/Avoid)**: **매도/진입 금지**. 하락 추세이거나 뚜렷한 방향성이 없는 횡보장입니다. (시스템 기본 매도 기준 `SELL_SCORE` = 4.0 / 보유 종목은 점수 미달 + **60일선 이탈**이 동시 충족될 때 매도)

## 3. 전략 파라미터 상세 (Configuration)

`config.py` 파일에서 **기본 전략(Global Strategy)**을 설정할 수 있으며, 프로그램 내 **'시스템 트레이딩 > 종목별 트레이딩 룰'** 메뉴를 통해 종목별로 개별 설정을 적용할 수 있습니다.
또한, **'메인 메뉴 > [0] 시스템 설정'** 메뉴를 통해 실행 중에도 전역 설정을 실시간으로 수정할 수 있습니다. (재시작 시에도 유지됨)

### 1. 기술적 지표 설정 (`INDICATOR_PARAMS`)
*   **데이터 조회 기간 (`CHART_LOOKBACK_DAYS`)**: 730일 (2년). 이동평균선(120일선 등)의 정확한 계산을 위해 충분한 과거 데이터를 조회합니다.
*   **RSI (상대강도지수)**:
    *   기간: 14일 (`RSI_PERIOD`)
    *   과매수 기준: 70 (`RSI_UPPER`) / 과매도 기준: 30 (`RSI_LOWER`)
*   **Parabolic SAR (추세 반전)**:
    *   가속변수(AF): 시작 0.02 (`SAR_AF_START`), 증가 0.02 (`SAR_AF_STEP`), 최대 0.2 (`SAR_AF_MAX`)
    *   값을 키우면 추세 반전 신호가 빨라지지만 속임수 신호가 늘어날 수 있습니다.
*   **CCI (상품채널지수)**:
    *   기간: 20일 (`CCI_WINDOW`)
    *   과매수/과매도 기준: ±100 (`CCI_UPPER`, `CCI_LOWER`)
*   **ADX (추세 강도)**: 기간 14일 (`ADX_PERIOD`). 20 이상일 때 안정적인 추세가 형성된 것으로 간주합니다.

### 2. 매수/분석 임계값 (`ANALYSIS_THRESHOLDS`)
*   **매수 기준 점수 (`BUY_SCORE`)**: 기본값 **7.0점**. 여러 기술적 지표(이평선, SAR, MACD, RSI, ADX 등)를 종합한 점수가 이 값 이상일 때 매수 신호가 발생합니다.
*   **상승 추세 점수 (`RISE_SCORE`)**: 기본값 **6점**. 매수 기준에는 미치지 못하지만 상승 흐름이 있는 상태입니다.
*   **관심 신호 최소 개수 (`INTEREST_SIGNAL_MIN`)**: 기본값 **3개**. 추세 정렬은 미완성이나 추세 전환 초기 신호 7종(단기 골든크로스·MACD 개선·+DI 우위·RSI 50선 상향·CCI 개선·수급 유입·60일선 근접)이 이 개수 이상 포착되고 위험 신호(MACD 데드크로스·-DI 우위·RSI 과열침체 등)가 없으면 **'관심'(태동)** 상태로 분류합니다. 120일선 아래여도 포착되며, 수동 스윙 매매 모니터링용입니다. (0으로 설정 시 미사용)
*   **관심 60일선 근접 비율 (`INTEREST_MA60_NEAR`)**: 기본값 **0.97**. 현재가가 60일선의 이 비율 이상(예: 97%)이면 아직 60일선 아래여도 '60일선 돌파 시도' 초기 신호로 인정합니다.
*   **매수 허용 RSI 상한 (`BUY_RSI_MAX`)**: 기본값 **70**. 매수 점수를 충족하더라도, RSI가 이 값 이상이면 이미 과열된 것으로 보고 진입하지 않습니다.
*   **매수 체결강도 기준 (`BUY_VOL_STRENGTH`)**: 기본값 **100.0%**. 매수 시점의 체결강도가 이 값 이상이어야 진입합니다. (매수세 우위 확인)
*   **역추세 매수 (`USE_MEAN_REVERSION`)**: 하락장이나 급락 구간에서 지표가 과매도에 도달한 후 반등하는 시점을 포착합니다. **(추세추종 기조로 기본설정·전 프리셋에서 비활성이며 설정 메뉴에도 노출되지 않음 — 재활성화는 `json/dynamic_config.json` 직접 편집으로만 가능)**
    *   `MR_RSI_MAX`: 역추세 진입 허용 최대 RSI (기본 40.0)
    *   `MR_DISPARITY_MAX`: 20일선 대비 이격도 제한 (기본 90.0% 이하)
    *   `MR_VOL_STRENGTH`: 바닥권 매수세 확인을 위한 높은 체결강도 (기본 120.0%)
*   **슈퍼 모멘텀 (`SUPER_MOMENTUM_USE`)**: 강력한 주도주(신고가 랠리)의 경우 매수 및 매도 RSI 허용치를 완화하여 추세를 길게 추종합니다.
    *   `SUPER_MOMENTUM_SCORE`: 발동 최소 종합 점수 (기본 8.0점)
    *   `SUPER_MOMENTUM_W52_POS`: 발동 최소 52주 고점 위치 (기본 90.0% 이상)
    *   `SUPER_BUY_RSI_MAX`: 발동 시 완화되는 최고 매수 허용 RSI (기본 80.0)
*   **피라미딩 (`PYRAMIDING_USE`)**: 수익으로 추세가 검증된 보유 포지션에만 증액합니다. (물타기 반대 개념, 손실 종목 증액 불가)
    *   `PYRAMIDING_PROFIT_TRIGGER`: 증액 발동 최소 수익률 (기본 +10.0%)
    *   `PYRAMIDING_RATIO`: 보유 수량 대비 증액 비율 (기본 0.5 = 50%)
    *   `PYRAMIDING_MAX_COUNT`: 포지션당 최대 증액 횟수 (기본 2회) — 4슬롯 포트폴리오 백테스트 기준 최적값

### 3. 매도 전략 (`SELL_STRATEGY`)
*   **손절 (Stop Loss)**: 손실률 **-7.0%** (`STOP_LOSS_RATE`) 도달 시 손실 확정.
*   **ATR 손절**: `USE_ATR_STOP`이 True(기본)일 경우, 고정 손절률 대신 매수 시점의 ATR × `ATR_STOP_MULTIPLIER`(기본 2.0) 만큼의 비율을 손절률로 사용합니다.
*   **ATR 최대 손절률**: `MAX_ATR_STOP_LOSS_RATE`는 데이터 오류나 과도한 변동성으로 손절폭이 비정상적으로 커지는 것을 방지하는 안전장치입니다. (기본값 -15.0%)
*   **본전 청산 (Break Even Stop)**: 달성한 최고 수익률이 `BREAK_EVEN_PROFIT_RATE`(기본 5.0%, ATR 사용 시 자동 연동) 이상 도달 시, 손절선을 `BREAK_EVEN_STOP_RATE`(기본 +0.5%)로 상향하여 수익을 방어합니다.
*   **시간 청산 (Time-based Stop)**: `TIME_STOP_USE`가 True일 경우, 매수 후 설정된 일수(`TIME_STOP_DAYS`, 기본 20일) 경과 시점에 수익률이 `TIME_STOP_MIN_PROFIT_RATE`(기본 **0.0%** = 손실 중인 종목만 대상) 미만이고 상방 모멘텀을 상실했으면 매도합니다. (상승 추세 유지 시 유예됨)
*   **트레일링 스탑 (Trailing Stop) — 주 익절 수단 (샹들리에 엑시트)**:
    *   **발동 조건**: 최고 수익률 **+10.0%** (`TRAILING_STOP_ACTIVATION_RATE`) 도달 시 감시 시작.
    *   **매도 조건**: 실효 콜백 = max(`TRAILING_ATR_MULTIPLIER`(기본 3.0) × ATR ÷ 고점, 최소 `TRAILING_STOP_CALLBACK_RATE`(기본 5.0%)). 급등주는 변동성에 비례해 콜백이 자동 확대되어 추세를 길게 추종합니다. (TS 전용 ATR 배수는 손절용 `ATR_STOP_MULTIPLIER`와 분리. `TS_MAX_GIVEBACK_RATIO`(기본 0=캡 해제, 순수 샹들리에)를 양수로 설정하면 최대 수익의 해당 비율 이상 반납 시 상한 캡 적용)
*   **추세 이탈 매도**: 종합 점수가 **4점** (`SELL_SCORE`) 미만으로 떨어지고 **주가가 60일선을 이탈**(추세 구조 훼손)하면 매도. 점수 하락 단독으로는 팔지 않으며(주청산은 트레일링 스탑에 위임), 상태가 '매도'로 분류되면 즉시 매도.
*   **역매수 유예 손절 (`MR_GRACE_LOSS_RATE`)**: 역추세 매수로 진입한 종목의 유예기간 중 최대 허용 손실률입니다. (기본값 -7.0%, 역추세 비활성 시 무관)
*   **기본 비활성 옵션 (상방 제한 요소 — 메뉴 미노출, `dynamic_config.json` 직접 편집 또는 종목별 개별 룰로만 활성화)**:
    *   **고정 익절**: `TAKE_PROFIT_RATE` = **0 (미사용)**. 값 설정 시 해당 수익률 도달에 전량 매도.
    *   **반익절**: `HALF_TAKE_PROFIT_USE` = **False**. 켜면 익절 목표의 절반 도달 시 50% 선매도.
    *   **과열 매도**: `TAKE_PROFIT_RSI` = **0 (미사용)**. 값 설정 시 RSI 초과에 선제 매도. (슈퍼 모멘텀 시 `SUPER_TAKE_PROFIT_RSI` 적용)
    *   **방어적 반매도**: `DEFENSIVE_HALF_SELL_USE` = **False**. 켜면 하락 반전 신호(SAR 매도 + 5일선 이탈) 시 50% 분할 매도.

### 4. 리스크 관리 및 필터링 (Risk Management)
*   **미국 주간거래(데이마켓) 시세**:
    *   **개요**: 미국 야간 ATS 세션(ET 20:00~04:00 = 한국시간 09:00~17:00, 서머타임 기준)의 실시간 시세를 반영합니다. KIS는 이 세션을 '주간거래(데이마켓)'로 부르며 **정규장과 다른 거래소 코드**(NAS→`BAQ`, NYS→`BAY`, AMS→`BAA`)로 시세를 제공합니다.
    *   **동작**: 데이마켓 세션 중에는 주간 거래소 코드를 먼저 조회하고, 해당 종목에 체결이 없으면 정규장 코드로 폴백합니다. 세션이 아닐 때는 기존 정규장 코드만 사용해 불필요한 API 호출을 만들지 않습니다.
    *   **거래소 캐시**: 조회에 성공한 코드가 주간 코드여도 `stock.json`·거래소 캐시에는 **항상 정규장 코드를 저장**합니다. 주간 코드가 저장되면 정규장 시간대 조회와 주문 경로가 함께 깨지기 때문입니다.
    *   **일봉 귀속**: 야간 세션 체결은 '다음 거래일' 세션에 귀속되므로(ET 21:00의 체결 = 다음날 세션), 시장 기준일도 세션 귀속일을 따릅니다. 이렇게 하지 않으면 주간거래 체결가가 확정된 직전 정규장 봉을 덮어써 지표가 오염됩니다.
    *   **배경**: 주문 경로는 이미 데이마켓을 인지해 주문 구분 `31`로 접수하고 있었으나 시세 경로가 정규장 코드만 조회해, 세션 내내 **직전 정규장 마감가가 그대로 굳는** 문제가 있었습니다. (실측: MU `NAS` $970.82 +12.17%[동결] vs `BAQ` $949.00 −2.25%[라이브]) '주문은 되는데 가격은 못 보는' 상태였습니다.
*   **슬리피지(Slippage) 보정**:
    *   **개요**: 주문 시점의 가격과 실제 체결 가격의 차이(불리한 체결)를 보정하기 위한 설정입니다.
    *   **백테스팅**: 매수 시 현재가보다 비싸게, 매도 시 싸게 체결된 것으로 가정하여 실제 매매 비용(호가 차이, 체결 지연 등)을 보수적으로 반영합니다.
    *   **실전/자동매매**: 시장가 주문(해외주식의 경우 현재가 기준 지정가) 시, 현재가보다 유리한 방향(매수: +0.1%, 매도: -0.1%)으로 주문 가격을 보정하여 급변하는 시세 속에서도 체결 확률을 높입니다.
    *   **설정값**: 기본값 `0.002` (0.2%). `config.py` 또는 설정 메뉴에서 변경 가능합니다.
    *   **추천 설정**:
        *   **대형주/ETF**: 0.1% ~ 0.2% (유동성이 풍부하여 호가 공백이 적음) - *권장*
        *   **일반/코스닥**: 0.3% ~ 0.5% (일반적인 시스템 트레이딩)
        *   **급등주/변동성**: 0.5% ~ 1.0% (체결을 최우선으로 할 때)
        
*   **Monte Carlo 시뮬레이션**:
    *   **개요**: 전략의 견고성(Robustness)을 검증하기 위해 노이즈를 추가하여 반복 테스트하는 기능입니다.
    *   **방법**: 가격 데이터에 ±1%의 랜덤 노이즈를 섞고, 슬리피지 변동 및 체결 누락(1% 확률) 등의 불확실성을 반영하여 1000회 반복 실행합니다.
    *   **결과**: 평균 수익률, 최악의 경우(VaR 95%), 수익률 표준편차 등을 통해 전략이 운에 의한 것인지 실력인지 검증할 수 있습니다.

*   **시장 지수 필터링**: KOSPI/KOSDAQ 지수가 이동평균선(기본 60일, `MARKET_FILTER_MA`) 아래로 하락하면 '하락장'으로 간주하여 신규 매수를 자동으로 보류합니다. **백테스트에도 동일 기준(설정값 그대로)이 반영**되어, 지수 약세일의 신규 진입이 차단된 결과로 시뮬레이션됩니다(실매매-백테스트 패리티).
*   **상대강도(RS) 필터 — 폐기 (기본 OFF, 설정 숨김)**:
    *   **폐기 사유**: '지수 대비 열위 = 신규 매수 금지'라는 이진 차단이 **추세 초입 진입과 정면충돌**합니다. 운영 유니버스 37종목×9년(2016~2026)의 실제 매수 신호 10,307건을 검증한 결과, RS 게이트는 신호의 28.6%를 차단하면서 대박(120일 +30% 이상) 비율 26.6%→25.4%, 손실(-10% 이하) 24.1%→25.0%, MDD -14.33%→-14.71%로 **모든 지표를 악화**시켰습니다.
    *   **원인**: 지수가 먼저 오른 국면에서 뒤늦게 돌아서는 종목(=추세 시작)이 항상 '지수 대비 열위'로 찍힙니다. 지수 6개월 모멘텀 +20% 이상 구간의 차단율이 39.9%로 가장 높은데, 그때 차단된 980건은 **48.6%가 +30% 이상 대박**이었습니다. RS 구간별 성과도 비단조(RS ≤ -30%p 구간의 대박률 43.9%가 전 구간 최고)여서 임계값 게이트로 성립하지 않습니다.
    *   **대체**: 유효 성분은 전부 종목의 **절대 모멘텀**이 갖고 있으며(스코어링 '가격 모멘텀' 팩터로 이미 반영), 절대 모멘텀 게이트에 RS를 덧붙이면 오히려 전 지표가 나빠집니다(대박률 28.7%→26.8%).
    *   **현재 상태**: `USE_RS_FILTER` 기본 `False`. 게이트 로직과 설정 키는 유지하되 시스템 설정 메뉴(메인메뉴 0)와 도움말에서 숨겨 임의 재활성화를 차단합니다. 필요 시 `dynamic_config.json` 직접 편집으로만 켤 수 있습니다.
*   **포트폴리오 동조화 방지 (Pearson Correlation Filter)**:
    *   **개요**: 특정 테마나 섹터에 자금이 집중되는 쏠림 현상(Concentration Risk)을 예방합니다.
    *   **작동 방식**: 신규 매수 후보 종목과 현재 보유 중인 종목들 간의 최근 일봉 수익률 피어슨 상관계수(Pearson Correlation)를 분석하여, 그 값이 설정된 임계값(기본 0.7) 이상으로 높게 동조화되어 있다면 신규 매수를 자동으로 보류합니다.
    *   **설정**: `USE_CORRELATION_FILTER` 및 `CORRELATION_THRESHOLD` (시스템 설정 메뉴에서 실시간 변경 가능)
*   **기술적 필터링 (2단계 안전장치)**: 
    *   **일반 필터**: MACD 데드크로스, 주요 이평선(60일/120일) 이탈 등 추세 훼손 시 **기본적으로 신규 매수를 보류**합니다. (단, 거래량 폭증 등 얼리 스테이지 매수 점수를 강하게 획득한 경우 예외적으로 진입을 허용하여 바닥권 반등을 포착합니다.)
    *   **절대 방어 필터**: ADX 45 이상이면서 매도세(-DI)가 우위인 **'초강력 투매 패닉 구간'**에서는 가짜 반등(휩쏘)에 당하지 않도록 점수와 무관하게 **신규 매수를 원천 차단**하여 떨어지는 칼날을 피합니다.
*   **일일 손실 제한 (방어 모드)**: 당일 추정 자산이 설정된 손실 한도(예: -10%)를 초과하여 하락하면 **신규 매수와 피라미딩 증액을 중단**합니다. 단, 시스템을 통째로 정지하지는 않습니다 — 손실 한도에 도달했다는 것은 이미 여러 포지션이 손절선 근처라는 뜻이므로, 이때 시스템을 끄면 손절·트레일링 스탑 감시가 함께 멈춰 포지션이 방치됩니다("손절을 하지 않으면 언젠가 계좌가 심각한 타격을 입는다"). 따라서 **노출을 늘리는 행위만 막고 청산 감시는 계속 동작**하며, 날짜가 바뀌어 당일 시작 자산이 재측정되면 자동으로 해제됩니다. 완전 정지는 사용자가 직접 판단합니다.
*   **시장 방향 판단 불가 시 매수 보류 (Fail-Closed)**: 지수 데이터 조회에 실패해 시장 방향을 알 수 없으면 신규 매수를 **허용이 아니라 보류**합니다("대체 무슨 일이 벌어지고 있는지 모르겠다면, 아무것도 하지 마라"). 매도·손절 경로는 지수 상태를 참조하지 않으므로 데이터 장애와 무관하게 계속 동작합니다.
*   **자동매도 제외 포지션 손절 경보**: 트레이딩 제한 종목(수동 홀딩)과 자동매매 대상에서 제외된 ETF는 시스템이 손절하지 않습니다. 이 포지션들이 손절선을 이탈하면 자동 청산 대신 **텔레그램 경보**를 보내 사용자가 직접 판단하도록 합니다. (동일 종목 재알림은 24시간 스로틀, 손절선 위로 회복하면 재무장)
*   **최대 보유 종목 수 (비중 자동 연동)**: 포트폴리오에 담을 수 있는 최대 종목 개수를 제한합니다. 종목당 비중(`SYSTEM_INVEST_PER_STOCK`)의 기본값은 **0 = 자동**이며, 이때 비중은 `1 ÷ 최대 보유 종목 수`로 산출됩니다. 따라서 **슬롯 수 하나만 바꿔도 명목합(비중×종목수)이 항상 100%로 유지**되어, 두 값을 쌍으로 맞추다 생기는 실수(0.3×4=1.2 → 앞순위 종목이 현금을 과다 소진해 뒷순위 슬롯이 굶음)가 사라집니다. 개별 종목 룰의 비중도 0이면 전역/자동값을 따라가므로, 저장 시점 값이 박제되어 슬롯 변경을 따라오지 못하는 문제가 없습니다.
    *   비중에 0보다 큰 값을 넣으면 자동을 무시하고 그 값을 그대로 사용합니다. 명목합을 100% 미만으로 두어 현금 버퍼를 남기거나(4슬롯 × 0.2 = 80%), 반대로 100%를 넘겨 **'슬롯은 넓게 열되 앞순위가 현금을 먼저 쓰게' 두는 의도적 오버커밋도 허용**됩니다. 초과 시 경고만 표시하고 차단하지 않습니다 — 신호가 드문 국면에서 현금을 덜 놀리려는 합리적 선택일 수 있기 때문입니다.
    *   슬롯 수 하한은 **승자 포착 확률**(승률 26% 기준 1-0.74ⁿ: 4개 70%, 3개 59%, 2개 45%), 상한은 **승자 희석과 유니버스 크기**(관심종목 수의 15~20% 이내)가 정합니다. 시드별 권장: ~200만 3개 / 300만~1,000만 4개 / 1,500만~5,000만 5개 / 5,000만+ 6개. 사이징은 자산에 완전히 비례하므로 시드가 커져도 투자율·히트는 동일하고 금액만 비례해 늘어납니다.
*   **연속 오류 방지 (Kill Switch)**: API 호출이나 시스템 오류가 연속으로 발생(기본 5회)하면 시스템을 대기 모드로 전환하여 계좌를 보호합니다.
*   **주문 상태 머신 (Order State Machine)**: 주문 접수부터 체결까지의 상태를 엄격하게 관리하여 중복 매수나 유령 포지션을 방지합니다.
*   **리스크 기반 포지션 사이징**: 1회 매매 시 계좌 대비 최대 손실폭(기본 4%)을 제한하여, 손절폭이 큰 종목은 자동으로 매수 비중을 줄입니다.
*   **손절 부재 시 매수 보류 (탈출 전략 없으면 진입 금지)**: ATR 손절이 꺼져 있고(또는 ATR 미확보) 고정 손절률도 0(미사용)이면 **신규 매수를 진행하지 않고 사유를 로그에 남깁니다**. 이 상태의 포지션은 청산 기준이 없을 뿐 아니라, 리스크 기반 사이징이 손절폭을 입력으로 쓰므로 **손실액 상한까지 함께 사라집니다**. 기본 설정(ATR 손절 ON, 고정 -7%)에서는 도달하지 않으며, 전역 설정이나 개별 종목 룰에서 둘 다 끈 경우에만 작동합니다.
*   **백테스트-실매매 데이터 일치**: 국내 백테스트는 **모드와 무관하게 KRX 공식(pykrx/FDR)** 을 씁니다(폴백: yfinance → 차트 API). 토스 모드는 실매매 지표가 이미 KRX 공식이고 KIS 일봉도 KRX 정규장 기준이라, 검증한 전략과 실행하는 전략이 같은 데이터 위에 서고 **모드를 바꿔도 백테스트 결과가 흔들리지 않습니다**. 분석 경로(`get_chart_data`)는 250봉(약 1년) 상한이라 장기 백테스트에 쓸 수 없으므로 소스만 같게 두고 조회 기간을 늘려 받습니다.
    *   **무언의 절단 방지**: 최종 폴백(차트 API)까지 내려가 확보 기간이 요청보다 짧으면 **노란 경고**로 알립니다. 종전에는 5년을 요청해도 250봉 상한에 걸려 1년치만으로 조용히 돌아갈 수 있었습니다.
*   **포트폴리오 히트 캡 (총 오픈 리스크 한도)**: 보유 전 종목이 '현재가→유효 손절선(BEP·트레일링 상향 반영)'까지 동시에 하락했을 때의 잠재 손실 합을 계좌 대비 일정 비율(기본 10%, `SYSTEM_MAX_PORTFOLIO_RISK`) 이하로 제한합니다. 종목당 리스크 한도가 개별 통제라면 이것은 '동시 다발 손절' 시나리오의 합산 통제로, 신규 매수는 남은 리스크 예산에 맞춰 투자금이 축소·보류되고 피라미딩 증액도 예산 초과 시 보류됩니다. 기존 포지션의 손절선이 본전/트레일링으로 올라오면 예산이 자연히 회복되어 매수가 재개됩니다.
*   **변동성 타겟팅 (Volatility Targeting)**: ATR 지표를 활용해 종목의 연환산 변동성을 목표치(기본 25%, `TARGET_VOLATILITY`)로 정규화합니다. 변동성이 클 때는 비중을 줄이고 작을 때는 늘리되, **확대 스케일이 종목당 명목 상한(기초 비중)을 넘지 못하도록 클램프**하여 특정 종목 몰빵을 방지합니다. (마지막 종목 매수 시에도 리스크 한도를 준수하여 비중 조절합니다)
*   **세 상한의 min 결합**: 매수 금액은 ① 기초 비중(집중 방지) ② 리스크 기반 상한(손실액 통제) ③ 변동성 상한(변동성 균질화)이 각자 낸 금액 중 **가장 작은 값**으로 정해집니다. ②와 ③을 곱해서 쌓지 않는 이유는 ATR 손절을 쓸 때 두 상한이 모두 ATR에 반비례해, 곱하면 사이즈가 `1/ATR²`로 과대 축소되기 때문입니다(고변동 종목에서 기초 비중의 21%까지 눌리고, 기초 비중을 올려도 최종액이 변하지 않는 현상이 발생). min 결합에서도 최종액은 항상 ② 이하이므로 손실액 상한은 그대로 지켜집니다.
    *   ⚠️ 종목당 비중(`SYSTEM_INVEST_PER_STOCK`)과 종목 수(`SYSTEM_MAX_HOLDINGS`)는 **집중도**를 정할 뿐 **투자율**을 정하지 못합니다. 명목합(비중×종목수)이 100%라면 4×0.25든 3×0.33이든 만재 투자율은 동일하며, 실제 투자율은 `TARGET_VOLATILITY`가 결정합니다.
*   **리스크 한도 동적 스케일링 (Risk Scaling)**: "자본대비 리스크·변동성에 한도를 둔다"는 추세추종 원칙에 따라, 신규 진입의 리스크 한도(종목당 리스크·포트폴리오 히트 캡)를 시장 국면과 계좌 상태에 맞춰 자동 축소합니다. 진입 '크기'만 줄이며 청산 로직(트레일링 스탑 등)에는 관여하지 않습니다.
    *   **국면 연동 축소**: 축소 대상은 확정 약세가 아니라 **하락 미확정(PendDown, 추세 붕괴 초기)** 구간입니다(기본 ×0.6, `PENDING_DOWN_RISK_SCALE`). 15년 백테스트상 확정 약세는 이미 5% 이상 하락한 뒤라 향후 20일 수익률이 오히려 양(+)이었고, 그 구간에서 리스크를 줄이면 CAGR만 깎였기 때문에 기본값은 미적용(×1.0)입니다.
    *   **휩소율 연동 축소**: 직전 8회 교차 중 확인 기준(5%)을 못 채우고 되돌려진 비율(휩소율)이 높을수록 = 톱니장일수록 진입 크기를 연속적으로 줄입니다. (기본: 휩소율 40% 이하 ×1.0 → 75% 이상 ×0.6, 사이는 선형 보간) 4개 국면 단독 대비 MDD를 크게 낮춥니다. (KOSPI -41.7%→-34.6%, KOSDAQ -47.8%→-36.9%)
    *   **드로다운 단계적 감속(터틀식)**: 계좌 자산 고점(HWM) 대비 하락률에 따라 리스크 한도를 단계적으로 줄입니다. (기본: -5% 이상 ×0.75, -10% 이상 ×0.5) 손실 구간에서 자동으로 베팅을 줄여 최대낙폭(MDD) 곡선을 완만하게 만들고, 회복 시 원복됩니다. (국면 배수 × 드로다운 배수는 곱으로 결합)
    *   **갭 리스크 버퍼**: 소프트 스탑(주기 감시 손절)이 갭하락으로 손절가보다 낮게 체결될 수 있으므로, 리스크 기반 사이징 시 손절폭에 버퍼(기본 ×1.2, `GAP_RISK_BUFFER`)를 곱해 보수적으로 투자금을 계산합니다.
    *   **피라미딩 시장 게이트**: 신규 매수가 차단되는 약세 시장(지수<SMA)에서는 검증된 수익 포지션이라도 증액(노출 확대)을 보류합니다.

### 5. 스코어링 가중치 최적화 (Scoring Weights)
*   **개요**: 매수 점수 산출 시 각 팩터(추세, 모멘텀, 강도, 시너지)가 차지하는 비중을 사용자가 직접 설정하거나 최적화할 수 있습니다.
*   **설정 항목**:
    *   `TREND`: 추세 팩터 가중치 (기본 4.0)
    *   `MOMENTUM`: 모멘텀 팩터 가중치 (기본 2.5)
    *   `STRENGTH`: 강도/수급 팩터 가중치 (기본 1.5)
    *   `SYNERGY`: 시너지 가산점 (기본 2.0)
*   **백테스팅 최적화**: 백테스팅 메뉴의 '가중치 최적화' 기능을 통해 과거 데이터 기반으로 가장 수익률이 높은 가중치 조합을 찾을 수 있습니다. 단일 백테스팅 실행 시 매수 점수·RSI 상한·익절/손절 비율(**'익절 미사용(TS 주도)' 기준선 포함** — 고정 익절 조합은 기조 대비 참고용 비교 결과)·**피라미딩 최대 차수(0~5차, 각 차수는 발동 조건이 허용하는 한 최대로 증액)**·가중치 조합별 최적화 분석이 자동으로 함께 수행됩니다.

### 6. 적응형 임계값 (Adaptive Thresholds)
*   **개요**: 시장 국면을 실시간으로 판정해 매수 기준 점수(`BUY_SCORE`)를 동적으로 조절합니다.
*   **판정 방식 (이중 EMA 교차 + 추종 확인)**: 에드 세이코타식 규칙을 사용합니다. 빠른 EMA(9일, β=0.25)가 느린 EMA(41일, β=0.05)를 교차하면 방향 전환으로 보되, **교차 이후 지수가 5% 이상 진행해야 '확정 추세'로 인정**합니다. 확정 전에 다시 교차하면 그 구간은 휩소(실패한 추세)로 집계됩니다.
*   **4개 국면**:
    *   **강세장 (Bull)** — 빠른EMA > 느린EMA, 교차 후 +5% 달성: 매수 기준 완화 (예: -0.5점)
    *   **상승 미확정 (PendUp)** — 상승 교차했으나 5% 미달: 기준 유지 (확정 전 완화는 하지 않음)
    *   **하락 미확정 (PendDown)** — 하락 교차했으나 -5% 미달, 즉 **추세 붕괴 초기**: 기준 강화 (예: +0.5점)
    *   **약세장 (Bear)** — 교차 후 -5% 달성: 기준 강화
*   **검증 (KOSPI·KOSDAQ 15년 백테스트)**: 구(舊) 방식(지수 vs EMA5 + ADX)은 연 71~73회 국면이 뒤집혀 사실상 노이즈였고 '약세' 판정이 전체 기간의 42%를 차지하면서도 향후 수익률 판별력이 없었습니다. 신(新) 방식은 연 12~13회로 안정화됐고, 향후 20일 지수 수익률이 Bull +2.9%/+0.9%, PendDown -0.5%/-0.6%로 명확히 갈렸습니다.
*   **설정**: `config.py`의 `MARKET_REGIME_PARAMS` 또는 설정 메뉴에서 보정값(`BULL_SCORE_ADJ`, `PENDING_DOWN_SCORE_ADJ` 등)과 판정 파라미터(`REGIME_EMA_FAST`, `REGIME_EMA_SLOW`, `REGIME_CONFIRM_PCT`)를 변경할 수 있습니다.

## 4. 시스템 아키텍처 및 안정성 (Architecture & Stability)

본 시스템은 다중 스레드(Multi-threading) 자동매매 환경에서 발생할 수 있는 동시성 문제와 API 통신 병목을 해결하기 위해 강력한 백엔드 아키텍처를 적용했습니다.

*   **DB 작업 큐 프록시 (Queue Proxy) 및 SQLite Lock 차단**: 
    *   **문제**: 여러 스레드(자동매매, 주문 감시, 텔레그램 봇 등)가 동시에 로컬 SQLite 데이터베이스에 쓰기를 시도하면 `database is locked` 에러가 발생하여 치명적인 주문 누락이 생길 수 있습니다.
    *   **해결**: `db_queue.py` 모듈을 통해 모든 DB 쓰기 작업을 중앙 집중화된 **단일 워커 큐(Single Worker Queue Proxy)**로 라우팅합니다. 이를 통해 다중 스레드 환경에서도 데이터 무결성과 완벽한 순차적 처리를 보장하여 DB Lock 문제를 원천 차단합니다.
*   **전역 스레드 풀 (Global Thread Pool)**:
    *   무분별한 스레드 생성으로 인한 메모리 누수와 컨텍스트 스위칭 오버헤드를 방지하기 위해 `executors.py`에서 시스템 전역 스레드 풀을 관리합니다. 차트 분석, 백테스팅, 비동기 데이터 조회 시 시스템 자원을 효율적으로 재사용합니다.
*   **동적 설정 검증 및 Thread-Safe 아키텍처**:
    *   프로그램 실행(자동매매) 중 터미널이나 텔레그램을 통해 매매 전략 설정이 변경될 때 발생할 수 있는 충돌을 막기 위해 락(`threading.RLock`) 메커니즘을 적용했습니다. 또한, `Pydantic`을 활용하여 사용자가 변경하는 파라미터 값의 타입과 범위를 실시간으로 엄격하게 검증합니다.
*   **주문 상태 머신 (Order State Machine) 및 Kill Switch**:
    *   주문 접수부터 체결, 취소, 부분 체결까지의 모든 단계를 추적하는 상태 머신을 구축하여 API 통신 지연이나 응답 누락으로 인한 '중복 주문'이나 '유령 포지션'을 방지합니다. 
    *   네트워크 불안정이나 API Rate Limit 등 에러가 연속으로 설정된 횟수 이상 발생하면 계좌를 보호하기 위해 시스템을 일시 정지시키는 Kill Switch 기능이 내장되어 있습니다.
*   **실시간 시세 단일 적용 (Unified Real-time Price)**:
    *   종목 분석 화면과 시스템 트레이딩이 **동일한 당일 시세로 지표를 계산**하도록, 당일 미확정 캔들의 종가/고가/저가를 실시간 현재가로 보정하는 로직을 단일 진입점(`indicators.apply_realtime_price`)으로 통합했습니다. 이를 통해 메뉴 분석과 자동매매 간의 점수 불일치를 구조적으로 차단합니다.
    *   국내 현재가/체결강도는 **KRX/NXT(대체거래소)를 한 번의 호출로 통합 조회**하며, 실전 모드에서는 NXT 장 시간대 시세까지 실시간 반영합니다. (시스템 트레이딩과 동일한 캐시 키를 공유해 중복 호출을 절감)
    *   **장 종료 후 KRX 종가 기준 (`USE_KRX_CLOSE_AFTER_HOURS`, 기본 ON)**: 모든 장(NXT 애프터마켓 20:00)이 끝난 야간·주말·휴장 중에는 종목 분석의 **현재가·지표를 KRX 정규장 종가로 고정**합니다. 그 시간대의 현재가는 마지막 NXT 체결가로 굳어 있는데, 이 값이 확정된 KRX 일봉의 종가를 덮어쓰면 EMA·RSI·CCI·ATR·52주 위치가 함께 흔들립니다. 과거 일봉이 전부 KRX 정규장 기준(pykrx/FDR)이므로 기준을 맞추는 쪽이 정합적입니다.
        *   실측(2026-07-24 SK텔레콤): KRX 종가 100,000원 vs 애프터마켓 20:00 99,700원 → **EMA5 94,805→94,705, RSI 61.8→61.54, CCI 231.6→230.10, 52주 위치 55.2%→54.8%**
        *   거래 시간대(프리 08:00~09:00, 정규장, 애프터 15:30~20:00)에는 종전대로 실시간가를 반영합니다. 살아있는 시장의 가격을 보고 대응해야 하기 때문입니다.
        *   **주문 가격 계산은 이 설정과 무관하게 항상 실시간가**를 씁니다. NXT 시간대에 KRX 종가로 지정가를 내면 호가에서 벗어나 체결되지 않기 때문입니다.
        *   설정 메뉴 `[0] → 5-3. 데이터·통신`에서 끄면 종전처럼 마지막 NXT 체결가를 반영합니다.
    *   **NXT 장 종료 후 현재가 유지**: 위 설정을 끈 경우, 실전 모드에서는 KIS가 NXT 시세를 주면 그 값을, 주지 않으면 **마지막 NXT 종가를 기억했다가 다음 거래일 개장 전까지** 현재가로 표시합니다(디스크 영속, 재시작 보존). (모의투자는 KIS API가 NXT를 지원하지 않아 항상 KRX 종가를 표시)
*   **실시간 WebSocket 시세·체결통보 (Real-time WebSocket)**:
    *   한국투자증권(실전/모의)의 **WebSocket 실시간 push**를 도입해, 보유·후보 종목의 현재가/체결강도를 REST 폴링 없이 수신합니다(`realtime.py`). 읽기 경로(`get_current_price`/체결강도)가 WS 캐시를 우선 사용하고, 미구독·끊김·비활성 시 **기존 REST로 자동 폴백**하므로 동작은 항상 보장됩니다. TPS 예산을 주문·잔고조회에 양보해 **시스템 트레이딩 처리량이 향상**됩니다.
    *   **시스템 트레이딩 종목 최우선 구독**: KIS는 단일 연결당 41건(종목×TR) + approval_key당 동시 연결 1개로 제한됩니다. 보유종목→매수후보 순으로 **시스템 트레이딩 종목을 항상 구독**하고, 남는 슬롯에 그 외 관심종목을 로테이션합니다. 국내 ETF 시스템 트레이딩 포함 여부(`SYSTEM_INCLUDE_ETF`)도 구독 우선순위에 반영됩니다.
    *   **실시간 체결통보(H0STCNI0/H0STCNI9)**: 주문 체결을 WebSocket으로 즉시 감지(AES256-CBC 복호화)하여, 검증된 체결 확정 로직(`ConclusionMonitor`)을 곧바로 깨웁니다. 모의투자의 체결 추정 지연(유휴 시 최대 수 분)이 **체결 즉시 수준으로 단축**됩니다. 체결통보 미수신·복호화 실패·HTS ID 미설정 시에는 **기존 주기 폴링으로 완전 폴백**합니다. (구독키로 **HTS 로그인 ID** 필요 — 아래 환경 변수 참고)
    *   **런타임 토글**: 사용 여부(`USE_WEBSOCKET`)는 **메인 메뉴 `[0] 시스템 설정 > 5-1`** 에서 변경 가능하며, **프로그램 재시작 없이** 즉시 적용됩니다(끄면 REST 폴백, 켜면 자동 재연결). WebSocket 연결·구독·체결통보 상태는 **INFO 레벨로 파일 로그**에 기록되어 모니터링할 수 있습니다. (토스증권은 공식 WS 미지원이라 REST 폴링을 유지합니다.)
*   **메모리 보호 (라즈베리파이 OOM 방어)**:
    *   라즈베리파이(1GB) 등 제약 환경의 장기 무중단 운영을 위해, 시세 마이크로 캐시와 차트 캐시에 **항목 수 상한**을 두고 초과 시 가장 오래된 항목부터 자동 제거(eviction)합니다. 전체 시장 스캔 시에도 메모리가 무제한으로 증가하지 않습니다.
*   **인터럽트 안전 예외 처리 (Interrupt-safe Exceptions)**:
    *   광범위한 `except:`(bare) 구문을 `except Exception:`으로 정비하여 `KeyboardInterrupt`/`SystemExit`가 정상적으로 전파되도록 했습니다. (Ctrl+C 응답성 및 안전한 종료 보장)
*   **API 호출 효율·속도 최적화 (TPS 최적화)**:
    *   KIS/토스 OpenAPI는 초당 거래건수(TPS) 제한이 있어, 모든 시세/주문 호출이 단일 전역 TPS 게이트를 직렬 통과합니다. 따라서 분석 속도는 "총 호출 수 ÷ TPS"로 결정되며, 다음을 통해 양쪽을 함께 개선했습니다.
    *   **적응형 동적 TPS (AIMD)**: 고정 마진(실효 18 TPS) 대신, 시작 마진에서 출발해 성공이 누적되면 실효 TPS를 점진 상향하고 `EGW00201`(초당 한도 초과)이 발생하면 즉시 곱셈 감소(백오프)하여 **적정 TPS로 자가 수렴**합니다. (서버/네트워크 상태에 맞춰 처리량 극대화)
    *   **NXT 시간대 게이팅**: 정규장(09:00~15:30)에는 KRX가 대표가이므로 NXT(대체거래소) 보조 시세 조회를 생략하고, NXT 단독 거래시간(프리/애프터)에만 조회하여 **정규장 종목당 호출을 약 절반으로** 줄입니다.
    *   **일봉 차트 디스크 영속 캐시**: 일봉은 하루 1회만 변하므로 거래일 단위로 디스크(SQLite)에 보존합니다. **재시작 후에도 같은 거래일에는 네트워크 재조회 없이** 즉시 복원하며(시작 버스트 제거), 과거일자 항목은 자동 정리합니다.
    *   **불필요 호가 조회 생략**: 호가창(매도/매수 잔량비)은 매수 수급 게이트가 활성화된 종목에서만 조회하여, 게이트를 끈 종목의 호가 호출을 제거합니다.
    *   **워커 풀 TPS 정합**: 종목 단위 병렬 분석 워커 수를 TPS에 비례하도록 정합시켜, 게이트 앞에서 대기만 하는 과다 스레드(메모리 낭비)를 방지합니다.

## 6. 필수 준비 사항 (Prerequisites)

이 프로그램은 **한국투자증권(Korea Investment & Securities)** 및 **토스증권(Toss Securities)**의 Open API를 기반으로 동작합니다.
프로그램을 정상적으로 실행하기 위해서는 사용할 증권사의 계좌와 API 접근 키가 필요합니다. (두 증권사 모두 등록하거나, 하나만 선택하여 사용할 수 있습니다.)

### 한국투자증권(KIS) 준비 절차
1.  **계좌 개설**: 스마트폰 앱('한국투자증권') 등을 통해 비대면 계좌 개설
2.  **KIS Developers 서비스 신청**: 한국투자증권 KIS Developers 접속 및 서비스 신청
3.  **모의투자 신청 (권장)**: 홈페이지/HTS에서 상시 모의투자 신청 (테스트용)
4.  **API Key 발급**: 마이페이지 > 내 서비스 > 발급받기 (실전/모의 각각 발급 가능)
5.  **(선택) HTS 로그인 ID 확인**: 실시간 **체결통보 WebSocket**을 사용하려면 KIS HTS 로그인 ID가 구독키로 필요합니다. (미설정 시 체결 감지는 기존 REST 폴링으로 동작)

### 토스증권(TOSS) 준비 절차
1.  **계좌 개설**: 스마트폰 '토스(Toss)' 앱을 통해 토스증권 계좌 개설
2.  **토스증권 개발자센터 접속**: 토스증권 Open API 홈페이지 접속 및 서비스 신청
3.  **API Key 발급**: 개발자센터에서 API Key(앱 키)와 Secret 발급

### 공통
1.  **환경 변수 등록**: 발급받은 Key와 계좌번호를 시스템 환경 변수로 등록 (아래 설치 방법 참고)
2.  **허용 IP(화이트리스트) 등록**:
    - **토스증권(필수)**: 토스 Open API는 **허용 IP 등록이 필수**입니다. 등록되지 않은 네트워크(모바일 테더링, VPN, IP가 바뀐 회선 등)에서 실행하면 `IP address not allowed` 오류로 **토큰 발급이 거부**됩니다. 프로그램을 실행할 서버/PC의 **공인 IP**를 개발자센터(앱 설정 → 허용 IP)에 등록하세요.
    - **한국투자증권(선택)**: KIS는 IP 등록이 필수는 아닙니다. 다만 API 키에 '고객 IP' 제한을 걸어 둔 경우에는 해당 IP에서만 접속됩니다. (연결 거부/시간초과 오류는 대개 **KIS 서버 점검·장애나 네트워크 문제**이므로, 먼저 서버 상태와 네트워크를 확인하세요.)
    - 라즈베리파이 등으로 상시 운영한다면 **고정 IP** 회선을 권장합니다. 공인 IP가 바뀌면 다시 등록해야 합니다.
    - 토큰 발급이 실패하면 프로그램이 **사전 점검(Pre-flight) 단계에서 현재 공인 IP와 원인별 안내를 출력**하니 이를 참고하세요.

*   `TOSS_APP_KEY`, `TOSS_APP_SECRET`: 토스증권 API Key

*   `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`: 텔레그램 알림 설정
*   `GEMINI_API_KEY`: (선택) 테마 분석용 Google Gemini API Key (발급받기)
*   `GEMINI_MODEL`: (선택) 사용할 Gemini 모델명 (기본값: `gemini-flash-latest`)
*   `GEMINI_FALLBACK_MODEL`: (선택) 무료 티어 한도 초과(429) 시 자동 전환할 폴백 모델 (기본값: `gemini-flash-lite-latest`)
*   `DART_API_KEY`: (선택) 국내 공시·배당·실적 조회용 OpenDART API Key ([발급 안내](#12--opendart-전자공시-연동-설정-disclosure-integration))
*   `TV_USERNAME`, `TV_PASSWORD`: (선택) TradingView 계정. 지수·미국채 금리 조회에 쓰는 tvDatafeed가 **로그인 모드**로 동작해 익명 대비 조회 한도·안정성이 좋아집니다. 미설정 시 종전대로 익명(nologin)으로 동작하며 파일 로그에 WARNING이 남습니다(로그인 성공 시 INFO). 발급 토큰은 `data/tv_token.json`에 7일간 캐시되어 재시작 때마다 재로그인하지 않습니다(잦은 로그인은 TradingView 캡차를 유발). 캡차가 뜨면 잠시 후 다시 시도하거나 브라우저에서 한 번 로그인한 뒤 재시작하세요.

**설정 예시 (`~/.htsrc` 등 셸 프로파일에 `export`로 등록):**
```sh
# 한국투자증권 (실전/모의)

export SIM_HTS_ID="myhtsid"    # 모의 (동일 ID면 KIS_HTS_ID 하나로 갈음 가능)
```
> 환경 변수를 추가/변경한 뒤에는 셸에 다시 반영(`source ~/.htsrc`)하고 **프로그램을 재시작**해야 적용됩니다.

*또는 `config.py` 파일을 직접 수정하여 기본 설정을 변경할 수 있습니다.*

## 9. OpenDART (전자공시) 연동 설정 (Disclosure Integration)

금융감독원 **전자공시시스템(DART)**의 OpenAPI를 연동하면 관심종목의 **공시 모니터링**, **배당·실적 캘린더**, **수급·물량 신호**, **재무 스냅샷**, **중대 공시 텔레그램 실시간 알림** 기능을 사용할 수 있습니다. (메인 메뉴 `[6] 종목발굴·재무분석` 하위)
> DART API Key는 **선택 사항**입니다. 미설정 시 국내 공시/배당 기능만 비활성화되며, 그 외 모든 기능은 정상 동작합니다. (해외 종목 배당·실적은 yfinance로 키 없이 조회됩니다.)

### 1. API Key 발급 (무료)
1. [OpenDART 홈페이지](https://opendart.fss.or.kr) 접속 → 우측 상단 **인증키 신청/관리** > **오픈API 이용신청**
2. 이메일 등 기본 정보 입력 후 신청 (가입 즉시 발급, 무료)
3. 메일로 전달된 **40자리 인증키** 확인 (또는 **인증키 신청/관리 > 오픈API 인증키**에서 확인)
4. 일일 호출 한도는 20,000건이며, 본 프로그램은 관심종목만 하루 단위로 조회하므로 한도 내에서 충분합니다.

### 2. 환경 변수 등록
KIS/Gemini Key와 동일하게 **환경 변수**로 등록합니다. (셸 환경변수 `export` 또는 `.env` 파일)
*   `DART_API_KEY`: 발급받은 40자리 OpenDART 인증키

### 3. 제공 기능 (메뉴 `[6]` 종목발굴·재무분석)
*   **`[5] 배당·실적 캘린더`**: 국내(DART 확정 배당금/시가배당률) + 해외(yfinance) 통합. 종목별 배당 주기(월/분기/반기/연)를 자동 판정해 **다음 예상 배당락일**을 표시하고, **'현금ㆍ현물배당결정' 공시가 있으면 원문에서 확정 배당기준일·주당배당금을 추출해 확정값으로 대체**. 국내 실적발표 예상일(전년 잠정실적 공시일 패턴)과 다음 정기보고서 법정 제출기한도 함께 안내 (ETF는 공시 대상이 아니라 제외)
*   **`[6] 공시 모니터링`**: 관심종목 최근 공시를 중요도(중대/관심)로 분류해 표시하고, Gemini AI로 **호재/악재 해석** 요약. 잠정실적(매출/영업이익/순이익·증감률), 유상증자(신주 수·희석률), CB/BW(권면총액·전환가), **공급계약(계약금액·매출대비%·상대방)**, **자기주식 취득/처분(예정금액·기간)**, **무상증자(배정비율·기준일)**, **감자(감자비율)** 등을 원문/전용 API에서 자동 추출해 함께 표시
*   **`[7] 수급·물량 신호`**: ① **자기주식 취득·처분·신탁계약 결정**(회사 단위 수급 신호 — 예정금액·수량·기간·목적), ② **메자닌(CB/BW/EB) 오버행 감시**(최근 3년 발행분의 전환가 vs 현재가, 잠재 전환물량의 유통주식 대비 비중, 최근 전환청구권 행사 공시 감지), ③ **무상증자 결정**, ④ 임원·주요주주 소유상황(elestock)·대량보유 5%(majorstock) 보고 기반 **내부자 순취득/순처분** 요약(종목별 **최근 보고일**·보고 건수·순증감) 및 상세
    *   ※ DART는 지분 변동사유를 제공하지 않아 **매매 외 사유를 패턴으로 제거**합니다. ⓐ 신규·재보고 시 보유 전량이 증감 칸에 그대로 들어오는 문제를 **보유수량 차분**으로 보정(예: 국민연금 재보고 `+1,281,813`은 실제 `+12,343`), ⓑ 임원 5인 이상이 같은 날 같은 방향으로 보고하면 **우리사주·스톡그랜트 등 일괄 지급**으로 보고 요약·상세 모두에서 제외(방향이 갈리면 실제 매매로 판단해 유지)
*   **`[8] 재무 스냅샷`**: 가장 최근 정기보고서(연결 우선) 기준 **매출액·영업이익·당기순이익과 전기(동기) 대비 증감률**, 누적 차감 방식으로 계산한 **분기 단독 영업이익(YoY)**, DART 계산 재무지표(**ROE·부채비율**) 일람
*   **공시 텔레그램 알림** (기본 ON): 백그라운드 스케줄러가 평일 주기적으로 관심종목의 **중대 공시**(유상증자·감자·자기주식·관리종목 지정·횡령배임 등) 발생 시 텔레그램으로 즉시 푸시 (중복 발송 방지, 유상증자 희석률 등 상세 포함). 비활성화는 `[0] 시스템 설정`의 `AUTO_DISCLOSURE_ALERT_USE`에서 가능

> 최초 1회 실행 시 종목코드↔DART 고유번호(corp_code) 매핑 파일을 내려받아 `json/dart_corp_map.json`에 캐시합니다(월 1회 자동 갱신).

> **접수일자 처리**: DART는 계열에 따라 날짜 필드 제공 여부가 다릅니다. 공시목록 계열(`list`/`elestock`/`majorstock`)은 `rcept_dt`를 주지만, **주요사항보고서 '결정' 계열**(자기주식·메자닌·무상증자·감자)은 `rcept_dt` 필드가 아예 없고 **접수번호(14자리) 앞 8자리**가 접수일자입니다. 시스템은 이 경우 접수번호에서 날짜를 복원해 표시·정렬에 사용합니다. (복원이 없으면 '일자' 칸이 공백이 되고, 날짜 기준 최신순 정렬도 함께 무효화됩니다)

## 10. AI 기반 투자 어시스턴트 및 테마 분석 (AI-Powered Assistant)

*   **개요**: Google Gemini(LLM)의 실시간 웹 검색(Search Grounding) 능력과 시스템의 정밀한 기술적 분석 데이터를 결합하여, 심도 있는 투자 인사이트를 제공하는 강력한 전천후 AI 비서 기능입니다.
*   **주요 AI 서비스**:
    1.  **AI 종목 심층 진단 (`/analyze <종목>`)**: 특정 종목의 현재 시스템 퀀트 점수, 주요 기술적 지표(RSI, ADX, MACD 등)의 상태를 기반으로 AI가 실시간 뉴스와 모멘텀을 종합 분석하여 향후 주가 전망 리포트를 작성합니다. (터미널 및 텔레그램 지원)
    2.  **시장 주도 테마 분석**: 현재 시장을 이끄는 핵심 테마 TOP 5와 그 상승 배경, 관련 대장주의 수급 동향, 향후 체크포인트 등을 상세한 마크다운 리포트로 정리하여 제공합니다.
    3.  **AI 장전 시황 브리핑**: 매일 장 시작 전(설정 시간, 기본 08:30) 밤사이 글로벌 주요 마감 데이터(미국 지수, 환율, 원유, 비트코인 등)와 핫이슈를 분석하여 오늘 한국 증시의 관전 포인트와 주도 예상 섹터를 텔레그램으로 자동 발송합니다.
    4.  **대화형 주식/경제 Q&A (`/ask <질문>`)**: "오늘 HBM 관련주가 왜 올라?", "최근 금리 인하가 환율에 미치는 영향은?"과 같은 사용자의 자유로운 질문에 최신 뉴스 기반의 정확하고 전문적인 답변을 즉시 제공합니다.
    5.  **AI 백테스팅 성과 진단**: 단일 및 몬테카를로 백테스팅 결과를 AI가 분석하여 전략의 유효성(승률, 손익비, MDD 등)을 평가하고, 종목 특성에 맞는 최적의 파라미터(진입 허들, 손절폭, 트레일링 스탑 배수, 가중치 등 추세추종 틀 안의 항목)를 구체적으로 제안합니다.
    6.  **AI 매매 복기 리포트 (Trading Autopsy)**: 매도 체결 시 진입/청산 사유, 수익률, 당시 퀀트 점수와 최근 뉴스를 종합하여 AI가 거래를 복기합니다. 승률이 낮고 손익비를 추구하는 추세추종의 특성상 **결과(수익/손실)가 아니라 프로세스**(진입이 규칙에 맞았는가, 청산이 설계대로 작동했는가)를 판정하며, 규칙대로 집행된 손실은 '규칙 정상 작동'으로 표기하고 단일 거래를 근거로 한 파라미터 변경은 제안하지 않습니다.
    7.  **AI 장 마감 종합 브리핑 (`/closing`)**: 오늘 하루 시장 흐름(코스피/코스닥) 분석, 현재 보유 종목 특이사항 진단, 그리고 당일 매매 내역에 대한 객관적인 평가와 복기를 종합하여 내일장 대응 전략을 제안합니다. (명령어 및 장 마감 후 자동 발송)
    8.  **AI 관심 종목 큐레이션 (`/curate`)**: 실시간 매크로 지표와 시장 상황을 종합하여 현재 자금이 몰리는 주도 테마와 대장주를 발굴, 사용자에게 관심 종목 편입 후보로 추천합니다.
    9.  **AI 차트 이미지 판독 (Gemini Vision)**: 종목 차트 분석(메뉴 `[3]`, 주봉/일봉 지원)에서 생성된 차트 이미지를 Gemini 비전 모델이 직접 판독하여, 캔들 패턴·추세선·매물대 등 사람이 차트를 보는 방식 그대로의 심층 진단을 제공합니다.
*   **AI 리포트 공통 안전장치**:
    *   **추세추종 기조 주입**: 매매·자산배분 판단이 나가는 모든 프롬프트(종목/지수/차트 분석, 백테스트, 매매 복기, 마감 브리핑)에 시스템의 운용 기조를 명시하여 고정 익절·저점 분할매수 등 반추세성 조언이 생성되지 않게 합니다. 특히 차트 판독에서는 **RSI 과매수·CCI 과열만을 근거로 한 매도 의견**을 명시적으로 금지합니다.
    *   **반증된 개선안 재제안 차단**: RS 필터, 데드캣 저점매수, 시장 국면 게이트 일원화 등 이미 백테스트로 기각된 항목을 폐기 근거(검증 신호 수, 지표 변화량)와 함께 프롬프트에 넘겨 같은 제안이 반복되지 않게 합니다.
    *   **확신도·반증 조건 표기**: 전망성 리포트는 단정적 예측 대신 조건부 시나리오로 서술하고, 결론에 확신도(높음/보통/낮음)와 **"이 판단이 틀렸다고 볼 관측"**(반증 조건)을 함께 제시합니다.
    *   **종목코드 사후 검증**: AI가 표기한 `종목명(6자리코드)`를 KRX 상장 목록과 자동 대조하여 **없는 코드·종목명 불일치·시총 1천억 미만**을 리포트에 표시합니다. (상장목록 조회 실패 시에는 오탐을 막기 위해 표시하지 않습니다)
*   **기타 트렌드 분석**:
    *   **네이버 테마 순위**: 국내 실시간 등락률 상위 테마 및 주도주 상세 정보를 크롤링하여 제공합니다.

### Gemini API 연동 및 키 발급 안내
본 시스템의 AI 기능은 구글의 **Gemini API**를 기반으로 동작하며, 실시간 검색 기능(Google Search Grounding)을 활용하기 위해 무료 API Key 발급이 필요합니다.

1. **Google AI Studio 접속 및 로그인**: [Google AI Studio](https://aistudio.google.com/) 접속
2. **API Key 발급**: 좌측 메뉴에서 'Get API key' 클릭 -> 'Create API key' 버튼 클릭
3. **무료 티어 확인**: 발급받은 키는 기본적으로 무료 티어(Free Tier)로 동작하며, 일일 요청 한도 내에서 과금 없이 사용할 수 있습니다.
4. **환경 변수 등록**: 발급받은 API Key를 시스템 환경 변수에 등록합니다.
   *   `GEMINI_API_KEY`: 발급받은 API Key
   *   `GEMINI_MODEL`: (선택) 기본값은 `gemini-flash-latest`입니다. 필요시 다른 모델명으로 변경 가능합니다.
   *   `GEMINI_FALLBACK_MODEL`: (선택) 무료 티어 한도 초과(429) 시 자동 재시도할 더 가벼운 폴백 모델입니다. (기본값: `gemini-flash-lite-latest`)

> **주의사항**: 구글 무료 계정의 경우 간혹 Search 도구 사용 권한 오류가 발생할 수 있습니다. 해당 오류 발생 시 자동으로 검색을 우회하여 응답하도록 예외 처리가 되어 있습니다.

## 11. 예약 주문 시스템 (Reserved Order System)

본 시스템은 일반 증권사 HTS에서 제공하는 단순 가격/시간 예약뿐만 아니라, 로컬 컴퓨터 자원을 백분 활용하여 **퀀트 점수 및 기술적 지표 기반의 차별화된 예약 주문**을 지원합니다. 등록된 주문은 백그라운드 감시 스레드가 3초 주기로 실시간 감시하며, SQLite DB를 통해 프로그램이 재시작되어도 영구적으로 유지됩니다.

### 주요 발동 조건 (9가지)
1. **스탑로스/하향이탈 (STOP):** 주가가 감시 목표가 이하로 하락 시 익절/손절 매도
2. **돌파/상향이탈 (BREAKOUT):** 주가가 저항선을 상향 돌파 시 추격 매수
3. **지정가 도달 (LIMIT):** 특정 목표가 터치 시 대기 주문 실행
4. **특정 시간 (TIME):** 지정된 시간(예: 당일 장 마감 무렵 15:20)에 무조건 주문 실행
5. **퀀트 점수 (SCORE):** 시스템이 산출하는 종합 퀀트 점수가 설정치에 도달하거나 하락할 때 실행
6. **RSI 지표 (RSI):** RSI 수치가 과매수/과매도 기준선을 돌파하거나 이탈할 때 실행
7. **트레일링 매수 (TRAILING_BUY):** 주가가 계속 하락하다가 바닥을 다지고 최저점 대비 N% 반등 시 추격 매수 (바닥 낚시)
8. **트레일링 매도 (TRAILING_SELL):** 주가가 상승하다가 최고점 달성 후 N% 꺾여서 하락 시 이익 보전 매도
9. **이평선 크로스 (EMA):** 주가가 특정 이동평균선(EMA)을 상향 돌파하거나 하향 이탈 시 실행

### 스마트 보호 로직
* **유효 기간 설정:** 당일, 이번 주, 이번 달, 무기한 등 유효 기간을 설정하여 기간 만료 시 자동 취소됩니다.
* **중복 매매 방지:** 예약 매도가 걸린 종목을 수동이나 자동매매로 전량 매도해버리면, 이중 주문 에러를 방지하기 위해 대기 중인 예약 매도가 자동으로 소멸됩니다. (신규 매수 시 과거 예약 매수 자동 취소 기능 포함)
* **네트워크 자원 최적화:** 장 마감 시간(20:00 ~ 08:00) 및 정규장 단일가 동기화 휴게 시간(08:50~09:00, 15:25~15:30)에는 API 시세 조회를 완벽히 차단하여 불필요한 트래픽 낭비와 모의투자 제한(초당 호출 횟수) 소진을 방지합니다. (해외 주식 주간 시간 차단 포함)
* **시장가 대체 실행:** 실행 단가를 `0` (시장가)으로 지정하면, 조건 발동 시점의 현재가로 보정되어 전송됩니다.

## 12. 모의투자 환경 유의사항 (Known Issues)

*   **미체결 내역 조회 오류**: 한국투자증권 모의투자 시스템의 API 버그로 인해, 주문이 정상적으로 접수되었음에도 `미체결 내역 조회` API가 빈 리스트를 반환하는 현상이 있습니다.
*   **대응책**: 본 시스템은 이를 해결하기 위해 **로컬 주문 상태 추적** 기능을 탑재하고 있습니다. API 조회 결과에 없더라도 로컬에 기록된 미체결 주문이 있다면, 설정된 시간 경과 후 자동으로 **강제 취소(Blind Cancel)** 및 **잔고 확인**을 수행하여 상태를 동기화합니다.
*   **대체거래소(NXT) 및 SOR 주문 미지원**: KIS OpenAPI 스펙상 모의투자 환경에서는 대체거래소(NXT) 시세 조회 및 SOR 통합 주문이 지원되지 않으며, 오직 한국거래소(KRX) 정규장 거래만 가능합니다. 따라서 모의투자 모드에서는 15:30 이후 NXT 장 시간에 매매 시도 시 에러가 발생하며, **종목 분석 화면의 시세도 정규장 종가에서 갱신되지 않고 멈춰 보입니다**(NXT 시세를 받아올 수 없기 때문). (실전투자 모드에서만 NXT 및 SOR 기능이 정상 작동합니다.)
